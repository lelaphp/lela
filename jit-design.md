# The third engine's JIT: module design

This is the design of record for the compiled tier. It is one living document: every section is at its current value, and the ledger below records each revision with what changed, why, and the check that would show it wrong. Git holds the dated versions. `research/jit-design.r1.md`, `research/jit-design.r2.md` and `research/jit-design.r3.md` are the three earlier revisions, kept unedited as records beside `research/jit-research.r1.md` and `research/llvm-research.r1.md`; they are not read for anything this file marks current, and the "highest `N` wins" naming rule no longer applies to this note. Design of record for the engine: `third-engine-design.md`. Research: `research/jit-research.r1.md` for every php-src citation (`§A` to `§F` below name its parts), `research/llvm-research.r1.md` for the LLVM question. Vocabulary: `CONTEXT.md`. Decisions: `docs/adr/0001` to `0006`. Architecture terms (module, interface, seam, adapter, depth, leverage, locality, the deletion test, design-it-twice) are the `codebase-design` vocabulary. "Design §5.8" names a section of `third-engine-design.md`; "r2 §5.8" names the record `research/third-engine-design.r2.md`.

**Question.** Where do the seams of `php_jit` and the `Tier` seam go, what is each module's interface (everything a caller must know: signatures, invariants, ordering, error modes, cost), what stays behind it, and how is each tested through its interface and nothing else?

**4. Revision 4 (2026-09-07).** A review of every design, the seams, the month-one to month-two transition and the harness found four things the interpreter must do so that the tier can exist that were stated as goals and not as mechanisms, two of which would have produced wrong behaviour under `jit.mode=force` on the first day, and a set of contracts stated more strongly than the code could keep. Eight changes:

1. **Compiled loops test the interrupt flag** (§4.3, §4.6, §2.2). php emits a `vm_interrupt` test in every compiled loop and tests it again at every exit (`research/data/jit-research/rfc-jit.md:118`; `php-src-jit-exit-points.txt:298`). Revision 3 removed the back-edge safepoint from compiled code and put nothing in its place, so `max_execution_time` and `pcntl` signals could not stop a hot loop, and the design of record's own witness `set_time_limit(1); for (;;) {}` would have hung under `force`. The trace's loop header now loads the request's interrupt flag through `ExitCtx` and exits when it is set; the `Resume` contract gains the interrupt check the loop already does at a back-edge.
2. **Recording is exclusive per request** (§4, §4.9). A kernel called during recording can re-enter PHP, reach a safepoint on another word, win a claim and start a second recording on the same request. php refuses this with a per-process flag and bumps the counter instead (`php-src-jit-hot-root.txt:30-33`). `JitRequest` gains a `recording` bit that `hot` holds through a guard, and `visit` never claims while it is set.
3. **The entry safepoint is raised by frame activation, not by a body handler** (§2.2). Revision 3 said `safepoint` runs "inside the first body opline after the `RECV*` prologue", and that opline can be any opcode: as written it was a compare per opline or a mutable handler table. The call handler that activates a user frame runs the prologue and raises `Site::Entry` before it reports `Pushed`, which is the shape the recorder already assumed at `Stepped::Pushed`.
4. **Request-scoped op arrays carry sealed words** (§3.2). `Jit::safepoint` read `func.word(at)` and cloned `func.published()` for every frame, but an op array from `eval` or an uncached include has no `Published`. A sealed word, all ones, decodes as `blacklisted` and never claims; `Func::published()` returns an option that no path on the hot side reads.
5. **`Mode::Off` touches no word** (§4). Thresholds at `u32::MAX` still bumped the shared counter on every safepoint on every thread, and a saturated counter would eventually have claimed. `Off` is one mode load and `Continue`; that is what G1 measures.
6. **Contracts restated where they were too strong.** The word ordering argument of §3.2 did not follow from a relaxed read; the sound rule is the fallback `run` already had, and it is now the contract. The crossing's invariant in §4.6 is restated per fiber stack. `types` gains the clobber rule for call-effect kernels. `step` and `Site::Loop` gain the fused compare-and-branch rule. `JMPZ` joins the `safepoint` column and the compiler asserts the invariant.
7. **Sizes and names corrected.** `tier.lock` is not a few dozen items once the kernels are in it; the kernels enter as one generated section. `opcache.jit_buffer_size` is the one name. `jit.mode` is accepted from any host and logged, since no startup ini can know its host.
8. **The tier bit question of `research/llvm-research.r1.md` D.9 is answered** (§4.5): a region is a table entry with the same `Entry` ABI, so the id space needs no bit.

Check: G5 under `force` with the time-limit and signal witnesses of §7; one `TRACE start` line while a nested recording would have opened; `Probe` sees `(Entry, 0)` once per call and never when a `RECV` throws; an `eval` op array's words read `Blacklisted`; G1 with the tier bound and `opcache.jit_buffer_size=0`.

## 1. The shape in one paragraph

`php_engine::execute` is generic over a trait `Tier` with one hook, `safepoint`; `Nop` is the month-one adapter and `php_jit::Jit` is the month-two adapter, bound once per `Engine` as a function pointer, with the tier's state declared by the tier itself through the extension mechanism. The compiler numbers the loop headers, the entry and the returns of every op array; publication allocates one opaque zero `Word` per safepoint inside `php_engine`'s `Func`, a request-scoped op array gets sealed words, and `php_jit::table` allocates one word per exit of every published trace; `php_jit::policy` alone gives the bits meaning, in one state machine, and a `TraceId` is one number in one space whichever word it is read from. `php_jit` has ten modules: `dispatch` drives the one state machine and the trace-to-trace loop, `record` is a loop over the interpreter's `step` and returns a record with an owned view of what it touched, `types` and `lower` are pure and meet at the value `TraceIr`, `lower` owns its backend and emits the interrupt test at the trace's loop header, `table` owns every published trace, the one lock, and a dual-mapped arena, `compiler` is the pipeline from a record to a published trace and runs it on its own thread, `policy` is thresholds and transitions with no side effects, `enter` is the one `unsafe` crossing, and `lib` is `Jit`. Externally the crate exports one item.

## 2. The `Tier` seam

### 2.1 Design it twice: what `step` returns

| | (A) `Option<FrameRef>` | **(B) Chosen: `Stepped`, the edge the loop took** | (C) The recorder installs a frame-chain observer |
|---|---|---|---|
| What the recorder learns | a frame, and infers push, pop, move and the entry pop by comparing it with a `prev` it read before stepping | one enum arm | a callback per push and pop |
| Where frame-chain knowledge lives | in `record`, outside the module that manages the chain | in the loop, which pushed, popped, moved or threw | in `php_heap::VmStack`, behind a hook every push pays |
| The generator case (`GENERATOR_CREATE` moves the frame to the heap) | a special case the recorder must know | `Stepped::Moved` | a third callback |
| The entry frame | a bit in the frame header the recorder reads | `Stepped::Done`; the loop knows its entry frame | the callback must be told |
| Cost per step | one pre-read, one or two compares | none beyond what the loop already knows | a hook on every push in every request |

(B) is chosen. The loop's body already knows which of five things a handler did, because it is the loop that did it; returning that fact costs a discriminant. (C) is Mahout's door again, on the heap this time.

The earlier design-it-twice tables, one hook against two (revision 2) and the recorder as a loop over `step` against a third `execute` instantiation or a per-opline flag (revision 2 §2.1), stand in the records; their conclusions are the interface below.

### 2.2 Interface

In `php_engine::tier`, on the tier face (§5.3):

```rust
pub trait Tier: 'static {
    /// The tier's state on a request: its engine state resolved once, as the request is laid, and
    /// what its visits keep on the request between them, as php's tracing tier keeps `JIT_G`
    /// (revision 66, #3144). Read at one place, `state`, with no lookup in the slot table the
    /// extensions' states stand in. `Nop`'s is `()`, and so is every tier's that keeps none.
    type State: Send + 'static;
    /// Called at three sites and nowhere else: in a backward `JMP*` handler with the jump
    /// target as `frame.opline` (Site::Loop); by the activation of a user frame, after its
    /// `RECV*` prologue has run without raising (Site::Entry); in `RETURN*` before the frame
    /// pops (Site::Return). `frame` is the frame the loop is executing, and `held` the op array
    /// the loop holds for it, which the site's word is read from (revision 63, #3144).
    fn safepoint(req: &mut Request, frame: FrameRef, site: Site, held: Held<'_>) -> Flow;
    /// The state a request of the engine `started` is laid with, where the engine binds the tier's
    /// loop; none where it binds `Nop`'s, and by default (revision 66).
    fn lay(started: &Started<'_>) -> Option<Self::State> { None }
    /// Which of php's execution hooks the tier replaces, as phpdbg's does (design revision 58).
    const HOOKED: Hooked = Hooked::NONE;
    /// Whether the tier holds the frame `execute` enters until it executes it (revision 16).
    const HOLDS: bool = false;
    /// State the tier needs, declared as an extension would declare it (design §4.4).
    /// Registered by `EngineBuilder::tier`; `Nop` declares none.
    fn extension() -> Option<Extension> { None }
}

/// The handler that has the number passes it: a backward `JMP*` carries its header's number, a
/// `RETURN*` carries its own, and the entry is always zero. A frame cannot know which site it
/// is at, so the number does not come from the frame.
#[derive(Clone, Copy)] pub enum Site { Loop(SafepointIdx), Entry, Return(SafepointIdx) }
impl Site { pub fn idx(self) -> SafepointIdx; }

/// The op array a holder holds for a frame: the one the loop has in hand at a site, or the one
/// an epoch holds for a trace that recorded it (`Epoch::held`). A handle and not `&OpArray`, so
/// the op array's layout stays off `tier.lock`; a visit reads its word at the op array's
/// `runtime_cache` offset, as php's counter handler reads `ZEND_OP_TRACE_INFO(opline, offset)`.
#[derive(Clone, Copy)] pub struct Held<'a>(/* &'a OpArray */);
impl Held<'_> {
    pub fn func(self) -> FuncRef;
    pub fn word(self, req: &Request, at: SafepointIdx) -> &Word;      // sealed for a request-scoped op array or past the last
    pub fn safepoint_at(self, at: SafepointIdx) -> Option<OplineIdx>; // the opline a site's number stands at
}

pub enum Flow {
    /// Nothing happened; run `frame.opline`.
    Continue,
    /// The tier ran code. `frame.opline` and the frame chain were changed and are consistent.
    /// The loop performs the interrupt check it performs at a back-edge, then the pending-exception
    /// check it performs after a `throw`-effect op, then dispatches from the given frame.
    Resume(FrameRef),
    /// The tier ran the serving's entry frame to its end: the serving is over and its return
    /// value is set. `execute` takes it as `Stepped::Done`, as php's JIT returns `ZEND_VM_RETURN`
    /// to `execute_ex` for a `ZEND_CALL_TOP` frame (`zend_jit_ir.c:2104`, `:2483`).
    Returned,
    /// A fatal, `exit` or memory-limit bailout was raised inside tier code.
    Bail(Bailout),
}

/// The tier's state the request was laid with, where it is an `S`: one check of its type and no
/// lookup (revision 66). None where the engine binds a loop that lays none, `Nop`'s.
pub fn state<S: Any>(req: &Request) -> Option<&S>;

pub struct Nop;
impl Tier for Nop {
    type State = ();
    #[inline(always)] fn safepoint(_: &mut Request, _: FrameRef, _: Site, _: Held<'_>) -> Flow { Flow::Continue }
}

pub fn execute<T: Tier>(req: &mut Request, frame: FrameRef) -> Result<(), Bailout>;

/// Run exactly one handler, the one for the opline at `frame.opline`, with `Nop` at the
/// safepoints, and report what it did. An exception the handler raised is left pending on
/// `req` and is not dispatched: `step` never runs `HANDLE_EXCEPTION`, so one call is one
/// handler and never an unwind. A fused compare-and-branch handler is one handler over two
/// oplines (design §5.8), and `Same` then names the opline after both.
pub fn step(req: &mut Request, frame: FrameRef) -> Result<Stepped, Bailout>;
/// `step` over the op array a trace holds for `frame`, out of `epoch`, the epoch it was taken
/// from: what the step kernel serves, with no share of a unit taken and no lookup of the frame's
/// function (revision 63).
pub fn step_held(req: &mut Request, frame: FrameRef, held: Held<'_>, epoch: &Epoch) -> Result<Stepped, Bailout>;

pub enum Stepped {
    /// The same frame; continue at `frame.opline`.
    Same(FrameRef),
    /// The opline pushed and activated a callee: its `RECV*` prologue has run, `Site::Entry` was
    /// raised with `Nop`, and `frame.opline` is the callee's first body opline. The loop would
    /// continue in it.
    Pushed(FrameRef),
    /// The opline popped `frame` and the loop would continue in its caller.
    Popped(FrameRef),
    /// The opline moved `frame` to the heap (`GENERATOR_CREATE`) and the loop would continue in the caller.
    Moved(FrameRef),
    /// The handler left an exception pending. `Threw` wins over a push or a pop the same handler
    /// did (a `RECV` type error during activation; a destructor throwing during a `RETURN*`), and
    /// its frame is the current frame after that push or pop: the frame `HANDLE_EXCEPTION` runs in.
    Threw(FrameRef),
    /// The opline popped the entry frame of the enclosing `execute`; there is no frame to continue
    /// in. An exception may be pending: php's leave helper returns to the native caller with
    /// `EG(exception)` set, and so does this.
    Done,
}
```

What a caller must know, beyond the signatures.

*Ordering.* `safepoint` runs inside two handlers and one activation: a backward `JMP*`, after operand reads and before the jump; `RETURN*`, after operand reads and before the pop; and the activation of a user frame by the `DO_UCALL` and `DO_FCALL*` handlers, and by `execute` for its own entry frame, after the `RECV*` prologue and before the first body opline. `step` runs one handler and nothing else, so a caller that wants safepoint behaviour during stepping reads the words itself (§4.1), and a caller that wants exceptions dispatched hands a `Threw` frame back to `execute`. `Site::Return` is never raised for the entry frame of an `execute`: the `RETURN*` handler compares `frame` with the stack's entry slot before calling the tier, so no adapter has to. `Site::Entry` is raised for the entry frame of an `execute`, as php's counter fires whatever the caller is; a trace that starts there ends at that frame's return (§4.1).

*Return roots.* A return root is php's: the caller's opline past the call (`ZEND_JIT_TRACE_START_RETURN` on `opline + 1`), whose counter is armed only where a compiled trace returns into a caller that has no trace of its own (`zend_jit_trace_setup_ret_counter`, `Z/ext/opcache/jit/zend_jit_trace.c:3404-3418`). `Site::Return`, the callee's `RETURN`, bumps and claims nothing (#3036). The landing's word is the engine's, one per opline of an op array, laid down sealed the first time a tier arms one of its landings (§3.2), and a return's site is where the tier reads it, from the caller the `RETURN` returns to (§4.9, revision 61).

*The prologue.* Activation is the call kernel's: it pushes the frame, positions `frame.opline` as php's `i_init_func_execute_data` does, skipping the whole `RECV*` run when the function has no typed parameters and was passed no more arguments than it declares, and starting at opline zero otherwise (`zend_execute.c:4426-4437`), runs the remaining `RECV*` handlers in a loop bounded by `OpArray.safepoints[0]`, and, if none raised, calls `T::safepoint(req, callee, Site::Entry)` and reports `Pushed`. If a `RECV*` raised, the exception is pending, `Entry` is not raised, and the report is `Threw`; php's counter on a typed function sits on opline zero and would have counted that call (design §5.6), which is the registry's third `trace` row (§4.1). A generator frame is activated the same way before `GENERATOR_CREATE` moves it, and is not activated again on resume. The comparison per prologue opline is paid once per call and never per body opline.

*Invariants a `Resume` must satisfy.* The resume frame is on the VM stack (frames never move, design §5.6); `frame.opline` is an opline of that frame's op array; every slot the tier wrote holds a well-formed zval with its type byte; a pending exception, if any, is on `req` exactly as a kernel would have left it; and the request's interrupt flag, if set, has not been consumed, because the loop consumes it after the `Resume`. `execute` returns `Ok(())` exactly when the entry frame has returned; there is no second meaning.

*Error modes.* `Bail` carries the same `Bailout` a kernel returns; there is no other error.

*The tier's state.* A visit reads what the tier keeps, its engine state and what its visits leave each other, at one place the request is laid with, not from the slot table the extensions' states stand in, which a lookup hashes the type into, and not as an argument beside `req`. A site handler holds only the request, and a state borrowed from the request cannot be handed beside `&mut Request` (the compiler refuses it, E0502). The loop's own holds are out of the handlers' reach without a dispatch parameter, which costs every handler a register. And an `Arc` cloned per visit is an atomic write to the engine's shared count. So no handler and no dispatch signature carries it, and the five site handlers are as they were. The engine binds the tier's `lay` with its loop, so an engine that binds `Nop`'s lays nothing. The state is `Send` and the request's alone, so what a visit writes there it writes through `Cell`s, reading the whole state once through the request it holds shared (revision 66).

*Cost.* `Nop` is one inlined function returning a constant; the branch on `Flow` folds; `Stepped` is a discriminant the loop already has in a register; `Site`'s payload is a `u32` the handler already loaded. The interrupt check after a `Resume` is one load per exit, never per opline.

*The entry frame.* What the loop needs at `RETURN*` is to know whether the frame returning is its entry frame. That is a slot on the VM stack:

```rust
// php_heap, heap.lock items
impl VmStack {
    /// The entry frame of the innermost `execute` on this stack. Per fiber, because the stack is.
    pub fn entry(&self) -> FrameRef;
    /// Pushed by `execute` on entry. The guard pops on drop, so an `Err(Bailout)` pops too:
    /// shutdown functions and destructors run `execute` again after a bailout.
    pub fn push_entry(&mut self, f: FrameRef) -> EntryGuard<'_>;
    /// The frame the loop is executing.
    pub fn current(&self) -> FrameRef;
}
```

Design it twice on where the fact lives: a bit in every frame header is written once per `execute` and read once per return, and costs a bit the heap does not otherwise need; a field on `Request` is the same two writes but must be saved and restored on every fiber switch, because two fibers are two `execute` nestings; a slot on the VM stack is the same two writes and is per fiber because fibers own their stack pages (design §5.11). The stack is chosen. A generator resumed by a nested `execute` is a heap frame; the slot holds its `FrameRef`, which the running resume keeps alive, and frames never move while they live.

### 2.3 How the tier reaches `execute` without a generic `Engine`

`execute` is called at request start and at every native-to-PHP re-entry (`__toString`, `usort` callbacks, destructors, autoloaders), and the re-entry sites are non-generic `api` code. So the choice is bound once:

```rust
pub type ExecuteFn = fn(&mut Request, FrameRef) -> Result<(), Bailout>;

impl EngineBuilder {
    /// Default is `Nop`. Binds `execute::<T>` for this engine's lifetime and records
    /// `T::extension`; `build()` appends what it returns after the bundle's extensions,
    /// so `.tier()` and `.extensions()` may be called in either order.
    pub fn tier<T: Tier>(self) -> Self;
}
```

One indirect call per entry and per re-entry, never per opline; php pays the same call through `zend_execute_ex`, and refuses to JIT when something else has taken that pointer (§A.11). The loop body is fully monomorphised. The tier's state is built and dropped in the same order and by the same code as every extension's (design §4.4, §7.1): last at startup and request start, first at request end and engine drop. A tier bound to an engine can therefore not lack its state.

### 2.4 Adapters, and the deletion test

| Adapter | Where | `safepoint` | `extension` |
|---|---|---|---|
| `Nop` | `php_engine::tier` | `Continue` | `None` |
| `Jit` | `php_jit`, public | `dispatch::safepoint` (§4.9): under `Mode::Off`, `Continue` before any word; otherwise the one machine over the `Func` word | `JitEngine` and `JitRequest` (§4) |
| `Probe` | `php_engine` tests only | pushes `(site, number, func)` to a `Vec` in a test request state | that request state |
| `Debugger` | `sapi/phpdbg`, through `php_sapi`'s re-export of the face | the gate: `Continue` unless a breakpoint is in the frame at `Site::Entry`, the session is stepping, or a watchpoint is live; then a loop over `step` that checks breakpoints, stepping and watchpoints between handlers and hands back with `Flow::Resume` | none: the debugging session is the host's, lent each request inside its sink (§2.4 below, #3011) |

**The debugging host is a `Tier` too** (revision 8, #1308): its `safepoint` is the gate and `step` is its loop, as the recorder's is (§4.1). php's phpdbg replaces `zend_execute_ex` with a loop of its own (`Z/sapi/phpdbg/phpdbg_prompt.c`), which is principle 1's second loop; here `execute::<Debugger>` is the same loop over the same kernels, instantiated only in the `phpdbg` binary, and `execute::<Nop>` pays nothing for it. php's phpdbg compiles the program at its prompt and executes it only at `run`, so `Debugger` declares `Tier::HOLDS` (false by default): `execute`, php's `zend_execute`, then raises no observer begin for the main frame, and the host raises it with `tier::begin` at `run`, so a program never run is never begun and never ended; `Request::push_frame` raises none (revision 16). A watchpoint is compared between steps and not found by page protection: php's `mprotect` handler only marks the page it faulted on and compares at the next opline boundary (`phpdbg_watch.c:47-51`, `phpdbg_print_changed_zvals` from `phpdbg_prompt.c:1773`), so the report is the same opline with the same old and new values, and a process-wide fault handler has no place in an engine whose requests share a process on threads. Page protection can come later as a filter in front of the same comparison without touching the seam. The debugger's policy lives with its host: `php_sapi` re-exports the tier face (`Tier`, `Site`, `Flow`, `step`, `Stepped`, the stack the host steps and the writes it makes) as locked items, since ADR-0008 keeps `sapi/*` off `php_engine`; a host reads frames, op arrays and the linked tables through the native face from its own tier, as an extension does, and `tier.lock` keeps the mechanism, the writes and nothing that reads (revision 15).

The session, with phpdbg's output state, is one value the host owns, `Session`, which it lends each request it serves inside the sink it lends the request (`out::Sink { session }`) and takes back with the sink at the request's end; the gate and the natives reach it through `tier::sink::<Sink>(req)`, a tier-face item no extension sees. It is not the tier's request state: php's `PHPDBG_G` spans the cycles of phpdbg's main loop, which this host serves as separate requests, and php reads it in `php_sapi_phpdbg_ub_write` and `php_sapi_phpdbg_log_message` with no request in hand, so what lives across requests lives with the host, the one party that outlives them (ADR-0005). If a second host needs lent state that is not its output's, `tier::sink` is generalised then (#3011).

Two production adapters make the seam real by the two-adapter rule; `Probe` is how the interpreter's safepoint placement is asserted, and it is the first user of `Tier::extension`, which is what tests the registration path in `php_engine` before `php_jit` exists.

Deletion test. Delete `Tier` and either `php_engine` checks a `cfg(feature = "jit")` word in three places and depends on `php_jit` (a cycle), or the check is a `dyn` call per back-edge (the door cost, §B.9). It earns its keep.

Month one. `execute::<Nop>` is the shipped loop. `step` exists from day 1 because the recorder, the unknown-opline path and, before either, `xtask`'s single-step debugging of a witness all want it; it is the `match` body called once, and its cost is nobody's but its callers'. The prologue-at-activation shape is month one's too, because the interpreter needs it to raise `Entry` at all.

## 3. The engine-level state word

### 3.1 Owner and count: design it twice

`php_engine::Func` is the owner, over the op array and a side table (revision 1 §3.1's argument: allocation at publication beside the `MapPtr` offsets the engine already assigns; one load at a safepoint, since `Func` is what the frame already holds; mutable-by-atomics state never enters the immutable unit format). One sentence three modules depend on: the unit cache stores `Published`, the engine-owned value that holds an `Arc<Unit>` beside the `Func` for each of its op arrays and the map-pointer offsets assigned at publication; a request holds an `Arc<Published>` for every unit it fetched, and a frame's `FuncRef` names a `Func` inside one of them or, for a request-scoped op array, a `Func` in request memory (§3.2). `Func`, and so the words, live in `Published` and not in the unit, which is what ADR-0001 requires.

| | (A) One word per opline | **(B) Chosen: one word per safepoint, numbered by the compiler** | (C) One word per safepoint, found by search |
|---|---|---|---|
| Words per `Func` | `oplines.len()`; three kinds of opline ever non-zero | `safepoints.len()`: loop headers, the entry, and returns | the same |
| How a safepoint finds its word | `words()[frame.opline_idx()]` | the entry is number zero; every backward jump to one header carries that header's number, and a `RETURN*` carries its own, in a field php leaves unused for that opcode, named per opcode in `ops.toml`; the handler passes it on `Site` | binary search of `safepoints` by opline index at every back-edge |
| What the unit learns | nothing | `OpArray.safepoints: Box<[OplineIdx]>`, the headers, the entry and the returns, immutable, produced by the compiler; one `u32` in an unused field | `OpArray.safepoints` |
| Op-array identity (design §6.1) | unchanged | unchanged: `Unit::dump` prints operands by the opcode's kinds from `ops.toml`, and an unused field is not printed; the field is compared as zero by `compile-identity` and as its number by nothing | unchanged |
| Cost at a safepoint | one indexed load | one indexed load from a field already in the opline | a search |
| Memory per engine | 4 bytes × oplines | 8 bytes × safepoints, plus 4 bytes × safepoints in the unit | 8 bytes × safepoints |

(B) is chosen. Which oplines are safepoints is a fact about the op array (a loop header is a backward jump target, the entry is the opline after the `RECV*` prologue, a return is a `RETURN*`), so it belongs in `php_unit` beside the line tables, under ADR-0001's rule that the unit format is a leaf below both the compiler and the engine; the mutable words stay in `Func`. The compiler numbers headers, not back-edges: a `foreach` with a `continue` has two backward jumps to one `FE_FETCH_R`, and php keeps one counter at the header (§A.3), so both jumps carry the header's number and one root is recorded, not two. `ops.toml` has one column, `safepoint`, naming the field for the opcodes that are sites: `result` on the backward jumps `pass_two` leaves, `JMPNZ` and `JMP`, on `JMPZ`, which is backward only after the optimizer's `INV_COND` (`zend_emit_cond_jump` does not invert on `BOOL_NOT`; `do { } while (!$x)` is `BOOL_NOT` then a backward `JMPNZ`), and on `RETURN`, `RETURN_BY_REF` and `GENERATOR_RETURN`, all six verified to leave `result` unused in every handler body and every emission at 8.5.9 (`RETURN_BY_REF` reads `extended_value`, which is why `result` is the field; design §5.7 has the full list of forward-only jumps). `FAST_RET` jumps to an earlier index and is not a back-edge. **The compiler asserts the invariant on every op array it emits**: every backward jump's opcode other than `FAST_RET` has a `safepoint` column and its target is a numbered header; a violation is a compile error in `php_compile`'s own tests and a failure of the `compile-identity` corpus sweep, never a loop that silently does not compile. The `Site::Entry` activation reads word zero and no field, which holds for a function with no `RECV*` whose entry is opline zero, and for a function whose only opline is a `RETURN`, whose entry word is number zero and whose return word is number one. A function with no loop and one return has two words.

### 3.2 Interface, and the second home

```rust
// php_engine::tier. Allocated as the epoch's cache holds a unit, one per safepoint of each of its op arrays, all bits zero.
#[derive(Default)]
pub struct Word { halves: [AtomicU32; 2] }
impl Word {
    pub fn halves(&self) -> &[AtomicU32; 2];   // the one accessor; the meaning of the bits is php_jit::policy's
    /// A word no tier ever acts on: all ones. What every safepoint of a request-scoped op array
    /// (`eval`, an uncached include, a closure declared in one) reads: one static word, no allocation.
    pub const fn sealed() -> Word;
}
#[derive(Clone, Copy)] pub struct SafepointIdx(pub u32);   // 0 is the entry
impl SafepointIdx { pub const ENTRY: Self; }
/// An op array as the tier names it: the map-pointer offset its unit's publication gave it, the
/// engine's for a held unit and the request's for a request-scoped one (revision 24).
#[derive(Clone, Copy, PartialEq, Eq, Hash)] pub struct FuncRef(/* MapPtrOffset */);
pub fn func(req: &Request, frame: FrameRef) -> Option<FuncRef>;
/// A hold on the request's epoch (design §5.14), `Send` and `Sync`: what a holder and a view keep.
#[derive(Clone)] pub struct Epoch(/* Arc<Arena> */);
pub fn epoch(req: &Request) -> Epoch;
impl Epoch { pub fn word(&self, f: FuncRef, at: SafepointIdx) -> &Word; pub fn held(&self, f: FuncRef) -> Option<Held<'_>>; }
/// A return root's word, the landing past a call (§2.2): one per opline of a held op array, laid down
/// sealed the first time a tier arms one of its landings, sealed until armed (revision 61).
pub fn landing(req: &Request, frame: FrameRef, at: OplineIdx) -> &Word;
impl Epoch { pub fn landing(&self, f: FuncRef, at: OplineIdx) -> &Word; pub fn lay_landing(&self, f: FuncRef, at: OplineIdx) -> Option<&Word>; }
/// The tier's one value for an epoch, its trace table (§4.5): made by the epoch's first request that asks,
/// a borrow of the request's hold; read back from a hold that outlives its request (revision 27).
pub fn epoch_state<T: Any + Send + Sync>(req: &Request, make: impl FnOnce() -> T) -> Option<&T>;
impl Epoch { pub fn tier_state<T: Any>(&self) -> Option<&T>; }
```

Each epoch's unit cache keeps one row per op array of every unit it holds, at the op array's map-pointer offset: the unit, the op array's place in it and its words, written once as the unit is held and never freed while the epoch stands, so a unit the cache replaces keeps its words until the restart (design §6.3). That row is the design's `Func`, and the epoch's rows are its `Published` (revision 24).

`php_engine` knows this much and no more: a `Func` carries one `Word` per safepoint, zero at publication or all ones when request-scoped, two atomics, never read by `Nop`. `Word` is `Default` because `php_jit::table` builds one per exit of every published trace. It is not `#[repr(C)]`, because compiled code never touches a word: every bump is `dispatch::visit` in Rust. The layout is `php_jit::policy`'s and is the same in both homes:

| Half | Bits | Meaning | Written by | How |
|---|---|---|---|---|
| `halves[0]` | 32 | count of visits while `cold`; saturating; reset to zero when a claim settles as `Abort`, as php's counter resets when it fires (§A.3) | `dispatch::visit` for a `Func` word and for an `Exit` word; `policy::settle` | relaxed load, add, relaxed store; lost updates accepted (§A.3, §B.3) |
| `halves[1][0..2]` | 2 | `cold` 0, `recording` 1, `compiled` 2, `blacklisted` 3 | `policy::claim`, `policy::settle` | compare-and-swap for `cold → recording`; release store for the rest |
| `halves[1][2..8]` | 6 | failed attempts (php's 16 fits) | `policy::settle` | same store as the transition that counts it |
| `halves[1][8..32]` | 24 | when `compiled`: a `TraceId`, the same number in either home; when `cold` after a failed attempt: the `Stop` it ended on, php's bad root cache entry for the opline (`zend_jit_trace_is_bad_root`), which `policy::bad_stop` reads (revision 25) | `policy::settle` | the release store that publishes, or the one that counts the attempt |

The sealed word is the one bit pattern `php_engine` knows: all ones decodes as `blacklisted` with attempts and id saturated, so `visit` returns `Continue` for it on the same arm as any blacklisted word, and no code in `php_jit` names the case. That `blacklisted` is the all-ones state is a layout invariant of `policy` with its own test (§4.7). A request-scoped op array therefore costs no word at all, reading the one static sealed word, the request's epoch is held only inside the holder closure a claim would build, and a claim is never built on a sealed word.

The two-halves argument stands, at 32 bits each: a racy store of a stale count touches only `halves[0]`. A `TraceId` is one number; a `Func` word names the root it enters and an `Exit` word names the side trace it enters, and neither `enter` nor `dispatch` composes anything. php's 1,024 roots and 128 sides per root are `Policy` limits that `table.publish` enforces in `Counts`; 24 bits hold sixteen million traces and are never the bound.

Ordering, stated as the contract it is. `policy::read` is a relaxed load, so a cold back-edge on aarch64 pays no `ldar`. `table.get`'s slot load is acquire and pairs with the release store `publish` makes after the code, the exits and their zero words are complete, so a thread that finds the slot filled finds the trace whole. A relaxed read of `compiled(id)` does not by itself guarantee that the same thread's slot load finds the slot filled, because the two locations are ordered only on the writer; what makes the design sound is `dispatch::run`'s rule that a missing slot is "not compiled", which returns to the interpreter at the site with nothing run (§4.9). In practice the window is the length of one release store and is never observed on the two targets, and the escape, if G5 ever names it, is an acquire load on the `compiled` arm alone.

Only safepoint oplines have a word, and the landings a compiled trace armed (§2.2, revision 61), laid down per op array, one per opline, the first time one of its landings is armed, so an op array no trace returns into costs none. Cost per engine: 8 bytes per safepoint plus 4 bytes per safepoint in the unit's `safepoints` table, shared by every request, 8 bytes per opline of each op array a trace returns into, plus 8 bytes per exit per published trace; G4 sees both in RSS. A word while cold is written by every thread that visits it, so a loop header hot on eight request threads at once is a contended line for the length of the threshold and a shared read-only line afterwards; the threshold bounds the contention, and `Mode::Off` writes nothing (§4).

### 3.3 Per-request, engine, or both

| | Per request: `MapPtr<[Feedback]>` (r2 §5.14) | **Engine: `Word` in `Func` (chosen)** | Both: heat per request, state in the engine |
|---|---|---|---|
| Allocation | one map-table entry per op array per request on first touch, before any heat exists (§F.6) | one allocation per publication | both |
| Can hold "is this compiled" | no: a request cannot see another's compile | yes | yes |
| Cross-request heat | none; php resets per request too (§A.3) but keeps its traces | accumulates; requests shorter than 127 calls still reach a compile | none |
| Cost at a safepoint | one map-base load plus an indexed load | one load | two |
| Decision criterion | G1 within the drift bound and F.3 shows every root heats within one request | G1 within the drift bound | G1 fails on the engine word alone, or F.3 shows per-request heat is enough and the map entry is cheaper |

The engine word. The design of record deleted r2 §5.14's feedback sentence (design ledger 7); type feedback is the trace record plus the run-time cache (§E.3). The third column is the written fallback, chosen by F.3's measurement on the Laravel skeleton under FastCGI (does any root cross `opcache.jit_hot_func` inside one request), not by argument.

`php_jit`'s line ceiling is its `[[crate]]` row in `seams.toml`, which `xtask budget` holds and no design document restates. `php_jit` is `#![deny(unsafe_code)]` with `#[allow(unsafe_code)]` on `code` and `enter`. Externally the crate exports one item. The tier's state:

`JitEngine` holds no lock of its own; the one lock is inside `TraceTable`, and the compiler's queue is a second, private one that no safepoint takes (§4.8). `Shared` exists because the worker thread needs the policy, the backend and a sink by `Arc` and `JitEngine` is owned by the engine, not the other way round, and it reaches the table through the epoch its job's claim holds (revision 27). It holds no log: a root's lines after its start are written by the pipeline to the request it runs on, and a `jit_debug` that asks for one compiles inline (§4.8, revision 34), so the worker writes none. When `Backend::new` fails at `JitEngine::new`, or `opcache.jit_buffer_size` is zero, or `opcache.jit` is off, or opcache does not start for the host and no `jit.mode` names a lane (`opcache.enable` off, or on the command line and in phpdbg `opcache.enable_cli` off, revision 44), the tier runs with `Mode::Off`: the engine binds `Nop`'s loop and does not ask it (below), no worker is spawned, `backend` is `None` and never read, and `opcache.jit_debug` is read as asking for nothing, so no line is logged: php never starts its JIT where opcache does not start (`accel_startup`, `Z/ext/opcache/ZendAccelerator.c:3210-3220`), nor under `opcache.jit=disable`, a refused setting or a zero buffer, so no bit is read and no line written whatever they ask (`gh13232.phpt`), and under `opcache.jit=off` it starts it and runs no trace, reading only its stubs' bits, of which this tier has none (revision 39). `TraceTable::new` does not fail: an arena that cannot be mapped, as on a target with no `Pages` adapter yet, is none, and each publish into the epoch's table numbers its trace under the same bounds and keeps no code, so its word reads compiled and every reader takes it as not (revisions 27, 34). Under `Mode::Off` the engine binds `Nop`'s loop and never asks the tier: `Jit::asked` answers the engine's start with `policy::Bound`, `Never` where php's tier can never start (opcache unstarted, `disable`, a zero buffer, a refusal, no `Backend`) and `Runtime` under `opcache.jit=off` with a buffer, since this tier reads the startup ini alone (§4.7), which #3139 is to change. Only `On` binds `Jit`'s loop, whose safepoint is outlined. G1 measured the per-safepoint `req.engine::<JitEngine>()` lookup this replaces (#3133; revision 59). The tier is not an extension: it is not under `ext/*`, does not depend on `php_ext`, and is not in the bundle's list. It uses the extension mechanism for its state because design §4.4 is the one mechanism for per-engine and per-request state and a second would fail its own deletion test.

The lock, stated where the rule lives. Design §4.4's "`E` may not contain a lock" names the trace table and the compiler's queue as the two engine-owned exceptions beside the unit cache; both are reached through the tier's own state and never through an extension's.

### 4.1 `record`

```rust
pub(crate) enum Start { Loop, Enter, Return, Side { parent: TraceId, exit: ExitId } }
pub(crate) struct TraceRecord { start: Start, root: FuncRef, events: Vec<Event>, stop: Stop }
pub(crate) struct Recorded { record: TraceRecord, view: UnitView }
pub(crate) enum Event {
    Op { func: FuncRef, opline: OplineIdx, op1: Sample, op2: Sample, data: Sample, branch: Option<bool> },   // whether a conditional jump, or the one a fused compare-and-branch serves, was taken (revision 26)
    InitCall { callee: Callee, began: Began },   // Callee: User(FuncRef), Native(Types), what a native declares it returns (revision 75); Began: Here, Before, php's FAKE_INIT_CALL (revision 72)
    Enter { func: FuncRef },                 // a PHP-to-PHP call followed
    Back,                                    // its return
}
#[derive(Clone, Copy)] pub(crate) struct Sample { tag: Tag, packed: bool, reference: bool, indirect: bool, class: Option<ClassId> }
pub(crate) enum Stop { Loop, Link(TraceId), Return, RecursiveCall, RecursiveRet, Interpreter, Trampoline, PropHookCall, BadFunc,
    NotSupported, Exception, TooLong, TooDeep, TooDeepRet, DeepRecursion, LoopUnroll, LoopExit, RecursionExit, InnerLoop, CompiledLoop,
    TooManyTraces, TooManyChildren, TooManyExits, CompilerError, MovedFrame, RequestUnit }
pub(crate) fn run(req: &mut Request, frame: FrameRef, start: Start) -> Result<Recorded, Bailout>;
impl TraceRecord { pub(crate) fn dump(&self) -> String; pub(crate) fn parse(s: &str) -> Result<Self, ParseError>; }
```

`run` is one loop. Before each opline it samples the three operands from the frame, following `IS_INDIRECT` and `IS_REFERENCE` and marking both, and pushes one `Op`; then it decides whether to step at all: it stops with `NotSupported` at `CATCH`, `FAST_CALL`, `FAST_RET`, with `Interpreter` at megamorphic calls and `INCLUDE_OR_EVAL`, with `MovedFrame` on a heap frame. It reads the `Func` word at the loop header, entry or return it has reached (the word is at the number the opline carries, or number zero for an entry): `compiled` at a loop header inside the trace stops with `CompiledLoop`, and `compiled` at a root it reaches stops with `Link(id)`, as php does at a handler that is a trace (§A.4); the id becomes the `link` of the trace's last exit (§4.2). A fused compare-and-branch is one `step` and one `Op`, with the direction taken in `branch`, as php's record keeps the branch on the comparison (unverified against `zend_jit_trace_record`); every other conditional jump's `Op` carries its direction too, since php reads where its trace went from the next record and from its `END` record's opline, which this record has not (revision 26). Then it calls `step` and matches:

| `Stepped` | The recorder |
|---|---|
| `Same(f)` | continues at `f`; at the root opline after a `Loop` start, closes the trace |
| `Pushed(f)` | tries `view.hold(req, f.func())`; a request-scoped op array cannot be held and stops with `RequestUnit`; otherwise pushes `Enter { func: f.func() }`, depth + 1, and reads `f`'s entry word |
| `Popped(f)` | pushes `Back`, depth − 1. At depth zero the root frame returned: for a `Loop` or `Enter` start the trace ends after it, and the lowering places php's IP guard on the unknown caller (§A.5); a `Return` start roots at the caller's landing past the call (§2.2), so its depth-zero `Popped` follows the return past its root only where php's recursive return does, behind the IP guard, and otherwise ends the trace (revision 61) |
| `Moved(f)` | stops with `MovedFrame` |
| `Threw(f)` | stops with `Exception`; `hot` hands `f` back to `execute` through `Resume` |
| `Done` | cannot occur: see below |

Calls begun before the recording (revision 72). A recording that starts in a frame with calls its `INIT_*` began and no `DO_*CALL` has made yet, the records above it on the stack (`tier::under_way`), writes each down first, the outermost first, as `InitCall { began: Before }`, php's `ZEND_JIT_TRACE_FAKE_INIT_CALL` (`zend_jit_trace_record_fake_init_call`, `Z/ext/opcache/jit/zend_jit_vm_helpers.c:631-682`), and so does a return it follows past its root into a frame with calls under way, as php's does at `:1189-1196`. The trace's sends and its `DO_*CALL` serve those calls as any other; compiled code reads such a call's room where the interpreter stands, `Stood.call`, which `enter` lays down for a trace that reads it before any kernel stood the frame.

Where a loop is rooted (revision 49). A `Loop` start roots at the opline php's trace roots at, the loop's header php's CFG finds, which `zend_jit_setup_hot_trace_counters` marks `ZEND_JIT_TRACE_START_LOOP` (`Z/ext/opcache/jit/zend_jit_trace.c:8963-8980`): for a `for` or a `while`, compiled with a `JMP` to its condition before its body, the condition, and for every other loop the opline its back edge lands on (`record::loop_root`). php's CFG is built over the op array its optimizer left, so a condition php folds is read as folded: a `while (true)` or a `for (;;)`, whose condition is a `JMPZ` or `JMPNZ` on a constant that takes it back to the body, which php's pass 1 makes a `JMP` (`Z/Zend/Optimizer/pass1.c:315-333`) and its block pass threads the `JMP` into the loop through, is rooted at its body, and its condition is no header, so the opline past a call that ends the body is a landing a trace arms (revision NEXT, #3317). The back edge's `Site::Loop` stands the frame on the body, so the recording, and the entry of the trace its word names, step the rest of the body to the condition through `step` first (`record::headed`), and a body that leaves the loop on the way, a `break`, a return or a throw, records and enters nothing and resumes where it went. A trace rooted at a condition keeps a second way in at the body, `types::BodyEntry`, which the back edge enters with the frame held to what the trace knows there and which declines, with no exit, to that step where it holds anything else (revision 53). A loop whose condition is one fused compare over variables and constants is recorded from behind it instead, the condition written down as the back edge served it and the body recorded on from where the frame stands, with nothing stepped (`record::behind`, revision 54). Both are kept as built and ADR-0006 is not amended for an engine site at the condition, as Mitchell ruled on #3178 (revision 70): php puts its loop counter on the header by swapping that opline's handler, which an op array byte-identical to php's and shared immutable (design §3.4) cannot take, so such a site would cost a test in every compare handler or a mutable handler table. A condition the fused compare does not cover, a call or a `TMP` operand, still steps one body through `record::headed` (#3204). A loop header met inside a recording is that opline (`record::header_at`), so a trace closes, links and stops at an inner loop where php's does.

The rule about an entry frame, stated with the stack's slot: an opline that leaves its frame, a `RETURN*`, a `YIELD*` or a `GENERATOR_CREATE` (revision 42), at depth zero is stepped only when the root frame is not `req.stack().entry()`, because when it is, the caller is native and there is nothing to follow; and a `Return` start never starts on an entry frame because `Site::Return` is never raised there (§2.2). So `Done` is unreachable from the recorder, and the arm is `unreachable!()` with that sentence beside it. Before stepping the recorder reads nothing it needs afterwards, because `Stepped` carries the frame to continue in and the arm says what became of the old one. A native call that re-enters the interpreter through a nested `execute` returns `Same` and is opaque, as php's `DO_ICALL` is; whatever that nested `execute` did at its own safepoints, it did not record, because the request's exclusion, php's `JIT_G(tracing)`, is set for the length of this `run`, on whichever execution the nested `execute` runs, a fiber's included (§4.9, revision 30). After each step it checks the length limit and stops with `TooLong`. A `Bailout` from `step` ends recording with no record and is the `Err` of `run`. The buffer is php's flat record (`zend_jit_internal.h:365-373`), one `Vec` bounded by `opcache.jit_max_trace_length`.

The owned view. `record::run` builds `Recorded.view` as it goes through the tier face's builders (§5.3): `hold(req, f)` accepts an op array whose unit is published and returns `false` for a request-scoped one, holding nothing. `Recorded.view` holds the request's epoch once. `hold_class(req, c)` holds nothing and accepts a class whose `ClassId` is published (`ClassId::is_published`), since a published row lives as long as the epoch (design §5.14 *Identities*). A request-scoped class is one whose `ClassId` is request-local: its link read a request-owned class, or the cache did not hold its unit (design §6.2). It is recorded as its id and guarded through the request's cache slot, and `UnitView::class` is defined only for a class `hold_class` accepted. `UnitView` is therefore a value that holds the request's epoch and the ids it accepted, and is `Send`; `types::build` needs nothing else, and runs on the compiler's thread (§4.8).

What recording costs, per opline, is one call into `step` and the `match` it runs; G7 reports it.

Tested: `dump` and `parse` are inverses, so a recorded trace is a fixture; `run` runs on a real request under `Capture` with `jit.mode=force`, and its `TRACE start/stop` lines are diffed against the oracle's on the seven kernels through `oracle::compare` with the divergence registry (`docs/divergence.toml`, kind `trace`). Three differences from php's traces are decided here, ahead of the recorder: a trace whose root is the entry frame of a nested `execute` stops with `Return` one opline earlier than php's (whether php's does the same at a native caller is unverified); when the root table fills this engine blacklists the one root that hit `Full` where php stops every counter handler at once (`zend_jit_stop_counter_handlers`, §A.4); and a typed function's call whose `RECV` throws is a root in php, whose counter is on opline zero, and not here, where `Site::Entry` is raised only after the prologue ran without raising (design §5.6, ledger 9). The third is a registry row today, because the interpreter already raises `Site::Entry` after the prologue. The first two have no engine half until `record` and `table` exist, and each enters the registry as an `open` row the first time the `TRACE` diff raises it, for a person to accept against that reading. The recorder's classification is a table over `Stepped`, and each arm is a fixture that drives `step` on a witness which takes that edge (a call, a return, a `yield` that creates a generator, a throw, a return trace, a `do { } while (!$x)` loop, a fused branch taken each way).

### 4.2 `types`

```rust
pub(crate) struct TraceIr { entry: Entry, frames: Vec<FrameInfo>, values: Vec<Value>, ops: Vec<Op>, guards: Vec<Guard>, exits: Vec<ExitSpec>, map_ptrs: Vec<MapPtrRaw>, end: End }
pub(crate) struct Value { slot: Slot, types: Types, def: Def, home: Home }   // Def: Entry, Phi { entry, back }, Op(OpId), Reload(OpId); Home: Memory, Register
pub(crate) enum Op { Line(Line), InitCall { frame, callee, began }, Enter { frame }, Back { frame, out, escapes } }   // Line: the opline, its operands and writes, the jump it is fused to (Fused::{Jmpz, Jmpnz}), its immediate (Imm::{Arg, Binary}), Form::{Inline, Step}, its own exit where an inline form cannot finish, and its unwind where a kernel it calls throws (revision 28; revision 45)
pub(crate) struct Guard { at: GuardAt, check: Check, exit: ExitId }   // GuardAt: Entry, Before(OpId), Within(OpId); Check: Type, Deref, Layout, Direction, Stands (php's IP guard, revision 41), Arm (a table's jump's target, revision 73), Room (php's stack check, revision 73)

pub(crate) struct Unwind { stores: Vec<Store> }   // where a throw leaves, taking no exit: php's exception stub (revision 45)
#[derive(Clone, Copy)] pub(crate) enum Landing { Plain, FreeTemps { op1: bool, op2: bool }, RestoreCall }
pub(crate) enum End { Loop(LoopHeader /* at: OpId, repeat: Loop | Call | Return, interrupt: Interrupt */), Leave(ExitId) }
pub(crate) enum Interrupt { Exit(ExitId), Stub(OplineIdx), None }   // php's ZEND_JIT_EXIT_TO_VM exit point, or its jit_stub_interrupt_handler, which takes none (revision 51), or no test, a recursive return's (revision 87)
#[derive(Clone, Copy)] pub(crate) struct ExitId(u16);
pub(crate) struct Abort { stop: Stop, why: &'static str }
pub(crate) fn build(rec: &TraceRecord, view: &UnitView) -> Result<TraceIr, Abort>;
```

Pure: a record in, an SSA over frame slots out, with php's guard set placed where a recorded type is narrower than what the op array alone implies (§E.5), aliased variables kept at guard strength (§A.4), `SMART_BRANCH` refused into one compare-and-branch whose mispredict exit lands on the opline the jump goes to the other way, where php's lands (§E.5; revision 50), and an `ExitSpec` per guard naming the slots that must be stored and the `Landing`. `End::Loop` names the position the back edge jumps to, for php's three stops that make a loop (`LOOP`, `RECURSIVE_CALL`, `RECURSIVE_RET`), and where its interrupt test leaves, or that a loop by recursive return takes none, as php's takes none (revision 87); the lowering puts the test there (§4.3). A trace that does not loop ends through `End::Leave`'s exit (revision 26). `Landing` is decided at build time (whether a temporary is live at the exit opline is a fact about the op array; whether an `INIT_FCALL` sequence is open is a fact about the record), and a link is a build-time fact on the exit a `Link` stop ends on. **The clobber rule.** A kernel call whose opcode carries the `call` effect in `ops.toml` may run user code, and user code may write any array, object or reference the trace holds a derived fact about; after such a call every memory-derived value in the lattice (an array's length or packed flag, a slot's type where the slot is reachable through a reference or a symbol table, a property offset's class) is reloaded or re-guarded, and only register-resident scalars the trace itself owns survive. A kernel with the `throw` effect and no `call` effect clobbers nothing but may exit. `Abort` is the recoverable half of `Stop` and counts toward the blacklist: it carries the stop it counts as, the record's own where it stopped on a failed attempt, php's `TOO_MANY_EXITS` past `ZEND_JIT_TRACE_MAX_EXITS`, and `CompilerError` where the record does not fit the op arrays its view holds (revision 26).

*As built* (revision 26, #2954). Every slot of every frame the trace touches holds one value at a time, typed by php's `zend_update_type_info` over the `MAY_BE_*` bits for the scalar core and anything past it; what a slot entered with is what the op array implies, a parameter its declaration (`UnitView::parameters`, php's `arg_info`) and a variable no opline makes a reference none. A guard is held once at entry for a value the root's frame entered with, by the inline op that computed it for an arithmetic's overflow and a fetched element's type, as php's code generator holds a guarded value it writes, and before the reading op otherwise; a loop's phi guard moves to its entry value where the back edge already has the type, or where what the back edge brings is made by an inline `ADD`, `SUB`, `MUL`, `+=`, `-=`, `*=`, increment or decrement over numbers, which then holds it long within itself and reruns where it overflows, php's `is_checked_guard` (revision 47). A variable of a file's own code (`UnitView::is_main`) or of a function that reads its variables by name is guarded at every read and never narrowed, and a reference's inner type is guarded at every read, which php's code generator does where its TSSA adds nothing. Each opline is `Inline`, the scalar core over the types its guards hold, or `Step` (§5.2). An inline element write, `ASSIGN_DIM` of a scalar by a long key to a variable's array that may be packed, writes in place where php's `zend_jit_assign_dim` does, the array held once, packed, the key below `nNumUsed` and the element there and counting nothing, and is served by its handler through `step` where php's code calls its helpers, so it takes no exit; php adds no layout guard to an array an `ASSIGN_DIM` was recorded writing packed, so the write tests the layout (revision 77). A compound write to an element, `ASSIGN_DIM_OP` of a number by a long key with `ADD`, `SUB` or `MUL` to a variable's array or the one the reference it holds refers to, is inline as php's `zend_jit_assign_dim_op` compiles it (`Z/ext/opcache/jit/zend_jit_ir.c:13528-13750`): written in place where `ASSIGN_DIM`'s write would be and the element is a long or a double, a long overflowing to a double, and served by its handler through `step` otherwise, taking no exit, as php's takes none where its record holds no element type, which this tier's recorder does not record; an array read by a long key through a reference is held to its layout at that read alone, `Check::Layout`'s `read` saying it is read through the reference, as php's code generator adds the packed guard to what `zend_jit_fetch_reference` left of it, its trace SSA knowing no type of a reference (`Z/ext/opcache/jit/zend_jit_trace.c:5830-5880`), and such a guard never moves to a loop's entry (revision 84, #2963). An exit lands at an opline the interpreter serves whole, the one that could not finish or, where it threw, the one that threw; a return to a caller the IP guard did not expect, and a link at a call or a return, leave the opline unset, as php's exit with no opline does. `RestoreCall` is the landing while a call compiled code began is under way, and `FreeTemps` that of a fetched element's guard that leaves past the fetch. The clobber rule reads again, as a new value, every live value a symbol table reaches or that may be a reference; an array the trace owns keeps its layout across a call, since no other code writes it without separating it first. A kernel with no `call` effect that still runs user code clobbers nothing: `INIT_ARRAY`'s and `ADD_ARRAY_ELEMENT`'s handler, whose null key's deprecation reaches an error handler and whose duplicate key releases the value it replaces (`Z/Zend/zend_vm_def.h:6278-6291`), and the release kernel compiled code calls for a temporary, which may run a destructor. What that code can write is a variable a symbol table reaches, which no write narrows and every read guards, a reference, whose inner type every read guards, or an array, which it separates first, so no fact the trace keeps is one it can change; php's code generator calls such an opline's handler and keeps every type and register across it (`Z/ext/opcache/jit/zend_jit_trace.c:6480-6493`) (revision 83, #3306). php's ranges and reference counts are not kept, so a long arithmetic php's range inference proves stays long carries an overflow guard here. Where php types an operand from its inference over the whole function, which this tier does not keep (revision 26: ranges, reference counts and a function-level static inference, each costing a guard and never a wrong answer), `types` guards that operand. A division is the first such case: php's switch leaves `DIV`'s and `ASSIGN_OP`'s `/=` operands out, typing them from that inference, so here they are guarded as a product's, without which a division at a loop's header saw the loop's phi as anything and was stepped on every turn; the inline division leaves through its exit at a zero divisor. The guard retires if the tier ever keeps php's function-level inference (#3149) (revisions 38 and 60, #3111's ruling). Revision 26's three omissions are reversed by ADR-0015, built by #3176. Places that leave with an equal `ExitSpec` naming an opline leave through one exit, as php's `zend_jit_trace_get_exit_point` reuses one whose opline, `flags` and stack map match (`Z/ext/opcache/jit/zend_jit_trace.c:168-185`), and `ZEND_JIT_TRACE_MAX_EXITS` bounds the exits so taken; a fetched element's guard names the slot its place copied the element into before it left, `Stored::Copied`, so no other place leaves through its exit. The stack map is the stores, a register per slot, and the known types, a slot's type where the value was made one or once a guard before the exit held it, php's `SET_STACK_TYPE`, so successive guards at one place, the entry guards among them, leave through exits of their own, and the entry guards stand in their slots' order, as php's code holds the types the trace entered with slot by slot (revision 48); `Grows::Never` is php's `ZEND_JIT_EXIT_TO_VM`, a loop's interrupt test, numbered after every exit of its body as php takes it where it closes the loop, and a fetch's element it does not find (revision 35; revision 45). An entered trace of a function with typed parameters numbers php's RECV exits ahead of its own: one ZEND_JIT_EXIT_TO_VM exit per RECV that has a type or ends the prologue, as zend_jit_recv takes them for a root frame whose argument count the trace does not know (Z/ext/opcache/jit/zend_jit_ir.c:10836 at 8.5.12), so every later exit, and the side trace grown from it, carries php's number. The prologue ran before Site::Entry (§2.2), so no code tests them; the loop's interrupt test leaves through the first, landing at the entry's opline, as php's reuses it at opline zero (zend_jit_trace.c:7246). (Revision 85, #3269's ruling.) Where the trace knows the callee of a function's call by its full name (an `INIT_FCALL` or an `INIT_FCALL_BY_NAME`), an argument's send is compiled as php's code generator compiles it once `frame->call->func` is known (revision 82, #2963): a `SEND_VAR_EX` or a `SEND_FUNC_ARG` to a parameter taken by value is a `SEND_VAR`, which leaves its variable's type as it was (`zend_jit_trace.c:2373-2382`), a `CHECK_FUNC_ARG` that finds its argument by value clears the call's by-reference bit inline, and the `FETCH_DIM_FUNC_ARG` after it is a `FETCH_DIM_R` (`:5822-5829`); a method's or a dynamic call's sends stay the handlers', since php guards that callee and this tier does not. A call into a frame the trace inlines stores the caller's register-held values to their slots as it enters (`Op::Enter`'s `stores`), as php's allocator keeps no register across one (`zend_jit_trace.c:3169-3180`).

The seam is the value `TraceIr`, not a builder trait, and `dump::render` is its second real consumer; a builder trait wide enough to hide Cranelift's `FunctionBuilder` is nearly as wide as Cranelift and is Dax's `LowerHost` again. `Backend` is built from `Policy` and holds the `OwnedTargetIsa` and its flags, so no module but `lower` names a Cranelift type, and a Cranelift version bump is one module's change. `Backend` is `Send + Sync` because it holds no per-compile state, which `lower` asserts at compile time (revision 28); each `compile` builds its own `Context`. The §D fallback, the IR backend, is a second body of `Backend` under a feature, behind the same two functions and the same `Compiled`; an LLVM backend would be a third (`research/llvm-research.r1.md` D.1) and is not built before G8 has a reading.

What the code is. Frame slots are loads and stores at `frame + const`; recorded scalars are `i64`/`f64` SSA values; each guard is `icmp` and `brif` to a cold block that stores the live scalars with their type bytes and returns its `ExitId` (§E.6); kernel calls go through one private emitter, `call_kernel(builder, symbol, args, exit)`, that emits the indirect call to the 64-bit constant, tests the returned `Status`, and branches to the exit block when it is non-zero, or to the opline's unwind block, which stores the registers and answers `UNWOUND`, where a throw is what leaves (revision 45), so a new line in `kernels!` needs no mirrored rule here; where the opline names neither the emitter answers `ABANDONED`, past every `ExitId`, and `enter` reads the fatal or the panic the wrapper kept, as it reads them before it lands any exit (revision 28). The frame chain is the engine's, and compiled code writes a known callee's push, its call and its leave in place over the frame's layout (§5.3, #3222's ruling, revision 79), as php's `zend_jit_push_call_frame`, `zend_jit_do_fcall` with `i_init_func_execute_data` inline and `zend_jit_leave_func` do (`Z/ext/opcache/jit/zend_jit_ir.c:8466-8650`, `:10016-10600`, `:11035-11263`): an inline `INIT_FCALL` of a user function, or a recursive call, whose push the recording found plain (`tier::PlainCall`) takes its room off the stack's top page, copies the header the request lays out for the call (`tier::call_image`), writes its slots `UNDEF` and its record on the frame table; the `DO_*CALL` the trace follows into it makes the frame in place, writing the activation's flags, entry opline and cache, the caller and the slot that takes the return, and stands the caller at the call, php's `SET_EX_OPLINE`; and a function's `RETURN` whose value is a scalar leaves its frame in place, testing as it leaves each variable `types` does not hold uncounted, as `zend_jit_free_cv` tests it, the `RETURN` a trace stops at among them, after which the interpreter goes on in the caller as it does after php's `zend_jit_trace_return` (`types::End::Return`). Each falls back to the kernel it stands for where the engine's own path refuses the plain case, which is the ruling's guards: a page short of the room or a full frame table at the push; the interrupt raised, or a callee's cache not laid down, at the call; at the leave a receiver, a closure, an annex, arguments past the parameters, a variable that owns something, a frame a native called or one off the top page, and for the `RETURN` a trace stops at the trace's end exit in place of a kernel. None takes an exit of its own, as php's code takes none there (#3203's measurement), and each writes the `Stood` its kernel would. A native's `INIT_FCALL` whose push the recording found plain is pushed in place as a user function's is, the header the request lays out for it (`tier::call_image`), as php's `zend_jit_push_call_frame` pushes a native's call, and its `DO_ICALL` is served by the `handle` kernel, as php's `zend_jit_do_fcall` calls the native's handler directly (`Z/ext/opcache/jit/zend_jit_ir.c:10511-10600`), compiled code writing where the interpreter stands past it where it knows the call left under way, and stepping it otherwise (revision 84). Every other inline `INIT_*` is the `push_call` kernel, which refuses a callee other than the recorded one before it pushes anything, an inline `RETURN` that does not leave in place, and a `DO_*CALL` the trace does not follow into its callee, are `step` (§5.2), and a `DO_*CALL` it follows and does not make in place is `call`, the handler's inline path with no dispatch (revision 65); each writes a `Stood`, where the interpreter stands after it, its frame's room, the room of its call under way, its op array and its opline, by which compiled code follows inlined calls and returns, writes a send to the call's slot, holds php's IP guard and reads the way a stepped jump went (revision 28). `Compiled.bytes` are final and hold kernel addresses as 64-bit constants; a 32-bit host is `Unsupported`. **The interrupt test.** For a trace that ends in `End::Loop` whose header tests the interrupt, every loop but one by recursive return (revision 87), the lowering loads the interrupt pointer from `ExitCtx` once at entry and, at the header, loads the byte it points to and exits when it is non-zero, through the exit `LoopHeader.interrupt` names, at the header opline with `Landing::Plain` (revision 26); the loop then performs the interrupt check under the `Resume` contract (§2.2) and the interrupt helper runs as it would have at the back-edge. Where `LoopHeader.interrupt` is `Interrupt::Stub`, which `types` decides as php's `zend_jit_trace` decides between an exit point and `jit_stub_interrupt_handler` (`Z/ext/opcache/jit/zend_jit_trace.c:7210-7228`), a root that does not loop by returning, whose code php's code generator would run keeping the instruction pointer it entered with (`zend_jit_trace_uses_initial_ip`: an opline php's code generator serves through its handler, `zend_jit_trace_handler`, as its switch decides over what the opline's operands may be, whatever this tier steps or serves inline, or one it compiles inline at the opline the pointer names whose code may call into php's runtime, which stands the frame there first, `jit_SET_EX_OPLINE`, while the pointer still holds the trace's first opline; revision 80) and which holds nothing in registers at the test, the test takes no exit: it answers `lower::INTERRUPTED`, `enter` stands the frame at the header, and `run` makes the loop's interrupt check through `tier::interrupted` and enters the trace again there, as php's stub handles the interrupt and goes on at the header's handler, which is the trace; a throwable a hook left pending resumes the loop to unwind it, and the timeout's fatal bails (revision 51). One load and one branch per iteration, which is php's cost (`rfc-jit.md:118`); a trace without a loop has no test, because it runs a bounded number of oplines before the interpreter's own check, and a recursive trace is bounded by `opcache.jit_max_recursive_calls`. A trace's body is a function on Cranelift's tail convention, entered through one prologue on the host's convention that `enter` calls, php's trace prologue; a link and an exit whose side trace is published each hand on by a tail call to the next trace's body, which lays the entry that trace reads (§4.6) as `enter` lays it and keeps bytes final (§4.4, #3229's ruling, revision 81). Where the jump finds no trace, or the request has not entered that trace through the crossing yet, the exit's number is answered as before and `dispatch` hands on (§4.9). The link tests the interrupt first where php's does, a side trace's link to its own root where the root loops (`zend_jit_trace_link_to_root`, `Z/ext/opcache/jit/zend_jit_ir.c:17418-17432`), and that test and the loop header's are one emitter.

**Observed calls** (revisions 11 and 43; design §4.3 seam 9). Compiled code emits observer events where php's JIT does (`Z/ext/opcache/jit/zend_jit_ir.c:4620-4717`): when an observer was declared at engine build, at every compiled call, return and native call, inlined ones included, it reads the callee's resolved slot at run time and calls begin unless the slot reads none-observed, and calls end when the frame is the current observed one; an observed call keeps its frame. When none was declared, nothing is emitted. As built, the read is the interpreter's: where an observer is declared, compiled code pushes, makes and leaves no call in place (revision 79; the recording reads `UnitView::observed`), so it serves every opline that begins or ends a call through its kernel, an inline `DO_UCALL`, `DO_FCALL`, `DO_FCALL_BY_NAME` and `RETURN` among them, and a native's call, a frameless call, a `YIELD` and a generator's return are stepped oplines, so seam 9's homes in the handler (`observer::call`, `returned`, `native_call`, `native_returned`) read the slot behind the engine's one word of how many observers were declared, as the loop's do. The lowering reads no observer state and emits nothing of its own, so an engine with no observer declared compiles the calls in place and a call costs compiled code no observer test.

**Observed opcodes** (design §7.1; revisions 13 and 43). When an extension declared an opcode other than `ZEND_BEGIN_SILENCE` and `ZEND_END_SILENCE`, the tier does not start for that engine, bound `Mode::Off` where the tier is bound, and php's warning is raised through the startup diagnostics, as `zend_jit_check_support` refuses (`Z/ext/opcache/jit/zend_jit.c:3743-3756`); at those two, compiled code tells the declared opcode's observers before the kernel. When none was declared, nothing is emitted. As built, the tier's engine start asks `tier::observes(start, opcode)` of every opcode but the two, php's `zend_get_user_opcode_handler(i) != NULL` once every extension's start has declared, and `Policy::check_support` runs the tier `Off`, reading no `opcache.jit_debug` bit (revision 39), with `Refused::ObservedOpcode`; the engine's first request raises php's `JIT is incompatible with third party extensions that setup user opcode handlers. JIT disabled.` at `Unknown` on line 0 through `raising::startup`, once, wherever php sets its tier up and so warns, opcache started for the host and `opcache.jit` on or off with a buffer (`Z/ext/opcache/ZendAccelerator.c:3253-3254`), `policy::SetUp::Yes`, and never under `disable` nor where opcache does not start (revision 44). The two silence opcodes are stepped, and `step` tells their observers before the handler, as the loop does.

Targets. `jit` is a default cargo feature on Linux and macOS for x86-64 and aarch64, the two platforms `code` has a `Pages` adapter for (§4.4); "which hosts" within them is answered by `Backend::new`, not by a feature list, and another operating system is a third `Pages` adapter if ever wanted. How Cargo expresses it: `php_jit` is an optional target-specific dependency of `php_bundle`, and the `Tier` alias is gated on `all(feature = "jit", any(the four targets))`, so the feature on a fifth target is `Nop` and not a build failure.

`marks` is what a profiler needs and what a debugger of a bad trace needs: `table` turns it into php's `PERF` map line and `PERF_DUMP` record (§4.5), and `xtask` prints a disassembly annotated by function and opline from the same table. It costs three words per recorded opline in `Trace` and nothing in the code.

Tested at the seam: CLIF text of `compile` for each fixture is a golden file, lowered for x86-64 on System V with the kernels at made-up addresses so the text is one on every host (revision 28); the compiled bytes run under `force` against the oracle; `Backend::new` on a host with no backend is a unit test with a stubbed ISA lookup; the interrupt test is one line of the golden for every loop fixture that takes one, and a recursive return's golden is held to none.

### 4.4 `code`: the arena, sealed by construction

```rust
pub(crate) struct Arena { /* one region of php's buffer's size, mapped twice; chunks of 64 KiB carved inside it, the last what the region leaves (revision 57) */ }
pub(crate) struct Code { entry: NonNull<u8>, len: usize, chunk: Arc<Chunk> }   // entry is in the execute view
pub(crate) type Entry = unsafe extern "C" fn(*mut ExitCtx, *mut Frame) -> u32;

impl Arena {
    pub(crate) fn new(capacity: usize, map_jit: MapJit) -> io::Result<Arena>;
    /// Copies `bytes` into a chunk through the write view, performs the cache maintenance the
    /// target needs against the execute view, and returns a handle into the execute view.
    /// Bytes are final: there is no API to write to a `Code` again.
    pub(crate) fn publish(&mut self, bytes: &[u8], align: usize) -> Result<Code, Full>;
}
impl Code { pub(crate) fn entry(&self) -> Entry; }
```

The arena holds as many bytes as php's buffer, `opcache.jit_buffer_size` rounded up to the page (`ZEND_MM_ALIGNED_SIZE_EX(jit_size, page_size)`, `Z/ext/opcache/ZendAccelerator.c:3257-3263`), carved into chunks of 64 KiB but the last, which holds what the region leaves: a buffer below one chunk is one chunk of its own length, held by the cursor inside it, so it fills where php's fills: php's size is observable, in the dump and in `opcache_get_status()['jit']['buffer_size']`, so design §3.1 has the engine copy it (#3112's ruling, revision 57). Chunks stay the unit of mapping and of reuse.

Design it twice on the protection rule:

| | (A) One mapping, flipped RW around each publish | **(B) Chosen: two views of the same pages** | (C) One mapping, written only before it is ever executable |
|---|---|---|---|
| macOS, `MAP_JIT` | sound: `pthread_jit_write_protect_np` is per thread | the same call; the two "views" are one address and the per-thread toggle, so the shape is one | sound |
| Linux, `mprotect` | unsound: protection is per mapping, so for the length of a compile the chunk is RW for every thread, including one executing a trace in it | sound: the execute view is `PROT_READ | PROT_EXEC` from `new` and is never remapped; the write view is `PROT_READ | PROT_WRITE`, is held only by the compile lock's owner, and is never executed | sound |
| Tail of a chunk | usable | usable | wasted once the chunk is sealed |
| Mappings | one | two | one |
| What the test can show | nothing: `HeapPages` has no protection | thread A loops in a trace in chunk 7 while thread B publishes into chunk 7, natively, on both targets | |

(B) is chosen. On Linux the arena is one `memfd_create` file of `capacity` bytes, created with `MFD_ALLOW_SEALING` and sealed against shrinking and growing, mapped twice as a whole with `MAP_SHARED`, once RW and once RX, and chunks are carved inside the region. On macOS it is one `MAP_JIT` anonymous mapping, the one-region rule of §B.8, and the per-thread toggle around each write, which is the same shape with the two views at one address; there is no process-wide protection change after `new` on either platform. `HeapPages`, the test adapter, is one allocation of `UnsafeCell<u8>` handing out two raw pointers to it; it tests the arena's bookkeeping, which is all a heap adapter can. The internal `Pages` seam is `map_pair(len)`, one span and its two views, `write(at, bytes)` through the write view, and `sync(range)` and `rx(at)` on the execute view's addresses, with the same two adapters (revision 19). Cache maintenance, stated once: on x86-64 nothing; on aarch64 the data cache is physically tagged, so after the write through the write view one sequence on the execute view's addresses suffices, `dc cvau` per line, `dsb ish`, `ic ivau` per line, `dsb ish`, `isb`, done by an inline-assembly routine in `code` or by `wasmtime-jit-icache-coherence`, and on macOS by libSystem's `sys_icache_invalidate`, which `code` calls over the bytes written. Whether a thread that later enters a reused chunk needs its own `isb`: on macOS aarch64, #2741's test entered a body on one thread per core and dropped it, published a different body at the same address of the reused chunk, and had a thread that had never entered the chunk, waiting on an atomic pointer with no system call before its entry, enter it; that thread read the new body in every round, with its own `isb` and without, so `code` asks none of it on macOS. The test cannot choose which core the entering thread runs on, so a stale fetch it did not meet is not one it excluded. On Linux aarch64, with two aliases, the question is still unverified and is settled by the same test on that target. On macOS `code` reaches the mapping and the toggle through `libc`, already in the lock. The three lifetime rules are carried by types inside `table`: publication under the compile lock, no write after publication, code outlives every call. **No byte is patched** (#3229's ruling, revision 81). php links a hot exit to its side trace by patching the exit's jump once the side is compiled (`zend_jit_link_side_trace` → `ir_patch`, `Z/ext/opcache/jit/zend_jit_ir.c:17413`), which writes code another core may be running, the hazard (A) is rejected for. Here each exit has an entry slot instead (`lower::EntrySlots`), a word beside the code whose address the code holds as a constant: null at publication, set once with release to the side trace's entrance, its body's address and its number, by the publish that placed the side, after the side's own slot in the table is written, and loaded with acquire by the exit's code, which jumps to the side where it is set and answers its `ExitId` where it is not. A slot never names code that outlives the code that reads it: a side is published only into the table its parent stands in, the parent's trace holds its slots and the side's trace its entrance, and the table drops every trace at once with its epoch (§4.5), so a trace running in a request whose epoch holds the table runs beside every trace a slot of it names. `Full::Code` is php's `COMPILER_ERROR`: the emit found no room in the arena, and the recording aborts as a recoverable stop that counts one attempt toward the word's blacklist (`zend_jit_trace.c:7612-7622`, `:8452-8461`); `Full::Traces` is php's `TOO_MANY_TRACES` (#3015). That the Linux mapping and sealing calls behave as described is unverified in the research note; §B.8 covers macOS only.

A stricter posture, in which the write view exists only between `publish`'s first and last store, is a `Pages` policy behind the same seam and is not the default: it costs two syscalls per publish and defends against an attacker who already has an arbitrary write, which is not a threat model the design claims. php leaves its whole buffer RWX under `PERF_DUMP` and `GDB` (`research/data/jit-research/php-src-jit-startup-protect.txt:46,121`); the dual map makes that unnecessary here. `MapJit` is a startup value from the policy.

Tested at the seam under Miri with `HeapPages`: chunk fitting, alignment, live counts, and that a `Code` dropped last frees its chunk. Natively, on both targets: `mov eax, 7; ret` on x86-64 and `mov w0, #7; ret` on aarch64 through the two views; the concurrent test above, a spinning trace in one chunk on one thread and a hundred publishes into the same chunk on another, asserting the trace's result on every iteration; and the reused-chunk test. On macOS aarch64 all three pass (#2741): `mov w0, #7; ret` returns 7, and the spinning body answered 7 on every one of its calls while the hundred landed and were entered.

### 4.5 `table`: the owner of every published trace

```rust
    /// finds it so is refused with `TOO_MANY_TRACES` and calls `stop`, php's `zend_jit_stop_counter_handlers`, after
    /// which `stopped` holds and dispatch claims no word of the epoch (revision 27).
    pub(crate) fn full(&self) -> bool;
    pub(crate) fn stop(&self);
    pub(crate) fn stopped(&self) -> bool;
    /// Lock-free: two loads, the second acquire. A slot is written once, so the borrow is the
    /// table's. `None` in the window §3.2 names, which means "not compiled" to the caller.
    pub(crate) fn get(&self, id: TraceId) -> Option<&Trace>;
}
/// The table of the epoch `req` started in, kept by `tier::epoch_state` (revision 27).
pub(crate) fn of<'r>(req: &'r Request, policy: &Policy) -> Option<&'r TraceTable>;
```

The id space is one. A root and a side trace are numbered from the same counter; `Trace.root` names the root a side belongs to (itself, for a root), and `Counts` keeps php's three bounds, `opcache.jit_max_root_traces`, `opcache.jit_max_side_traces` per root, and `opcache.jit_max_exit_counters`, as numbers, not as widths. The read side is a segmented array, a fixed table of segment pointers each holding 1,024 slots, allocated on demand under the compile lock and read with two loads. A slot is written once and never cleared within its epoch, so `get` borrows the table, and entering a trace clones nothing and changes no count. A `Func` word's 24 bits and an `Exit` word's 24 bits hold the same kind of number, and `get` is the only reader of either. **`Kind` is the answer to the tier bit question** (`research/llvm-research.r1.md` D.9): a month-three region over hot traces is a table entry with the same `Entry` ABI, entered from the same word by the same id, and the word's layout does not change for it.

The lifetime rule. A trace's code embeds addresses from the units it inlined and the published classes it read, and all of them live as long as the epoch (design §5.14 *Identities*, §6.3). So the trace table belongs to the epoch: the epoch's arena keeps it in the one slot the tier face gives the tier (`tier::epoch_state`, `Epoch::tier_state`), made by the epoch's first request that asks and dropped with the arena, so `php_engine` learns nothing of what it is (revision 27). A request reaches only the table of the epoch it holds, and a restart starts the next epoch with an empty table, as `zend_jit_restart` resets php's buffer. The old table and its code are freed with the old epoch, once no request, job or claim holds it. No trace is freed alone. When `opcache.jit_max_root_traces` is reached, the table stops the hot counters and compiles nothing more until the restart (`:8164-8167`). A full code arena stops nothing: each compile that finds no room aborts as `COMPILER_ERROR`, as php's does (#3015).

Observability. php's `opcache.jit_debug` bits `PERF` (0x10) and `PERF_DUMP` (0x20) (`research/data/jit-research/php-src-jit-header.txt:59-60`) are honoured with php's outputs: under either bit a line per trace in `/tmp/perf-<pid>.map`, `<start> <size> TRACE-<n>$<where>$<line>` (`ir_perf_map_register`, `zend_jit_trace_name`), and under `PERF_DUMP`, on Linux alone, where php's `ir_perf_jitdump_open` finds an ELF executable, a `JIT_CODE_LOAD` record with the name and the code bytes in `/tmp/jit-<pid>.dump` (`ir_perf_jitdump_register`); php writes no line entries, so the `marks` are not written there and stay the disassembly's. php opens each file once per process, truncating it; here the engine's start truncates both, writes the jitdump's header and maps it once, the event `perf inject` finds it by, each epoch's table appends one write per line or record, numbering its records from the engine's one `code_id` as php's one static does, and the engine's end writes php's `JIT_CODE_CLOSE` record (revision 27). Both are written by `publish` under the compile lock. Nothing is written when the bits are clear.

Tested at the seam under Miri with `HeapPages`: publish, get, ids across a segment boundary, `Full` for each of the three bounds, a full table that stops compiling, a new epoch's table that starts empty, a publish that panics and leaves `Counts` unchanged, and that a dropped trace returns its chunk. Natively, `mov eax, 7; ret` (`mov w0, #7; ret` on aarch64) runs through `publish` and `get(..).code.entry()`. The `PERF` line is diffed against php's for one trace of one witness.

### 4.6 `enter`: the crossing

```rust
pub(crate) enum Left { Exit(Exited), Unwound(FrameRef), Interrupted(FrameRef) }   // an unwind hands back the frame that stands, nothing landed (revision 45); the stub the frame stood at the loop's header (revision 51)
pub(crate) struct Exited { exit: ExitId, frame: FrameRef }
/// Call the code with the request's trace number the trace's for the call, resume a panic a
/// wrapper caught, return a bailout a wrapper caught, and otherwise land the exit: read the current
/// frame from the VM stack, set its `frame.opline`, and release the temporaries a `FreeTemps`
/// landing names; a throwable a kernel left pending is not landed (revision 32).
/// Reads no word and follows no link: what happens next is `dispatch`'s.
pub(crate) fn enter(req: &mut Request, frame: FrameRef, trace: &Trace) -> Result<Left, Bailout>;

/// The first argument of every trace and every kernel wrapper. A local of `enter`. Compiled code
/// reads `req` at offset zero and `interrupt` at offset eight and nothing else; `pending` has no C
/// layout and is the wrappers' alone. It borrows the request for its life; generic over the request
/// so that `enter`'s own tests and the bench cross it without an engine (revision 20).
#[repr(C)] pub(crate) struct ExitCtx<'a, R = Request> { req: *mut R, interrupt: *const AtomicBool, pending: Option<Pending>, lent: PhantomData<&'a mut R> }
pub(crate) enum Pending { Bailout(Bailout), Panic(Box<dyn Any + Send>) }

#[repr(u32)] pub(crate) enum Status { Continue = 0, Exception, Bailout, Panic }   // produced by wrappers alone, branched on by compiled code

kernels! {                                   // lower::Kernel's five (revisions 28, 32, 65)
    Request => mod wrapped {
        Step => step(func: u32) -> Stood = tier::step_held;     // the opline of the op array numbered func served whole (§5.2)
        PushCall => push_call(func: u32, callee: u32) -> Stood = tier::step_held;   // an inline INIT_* where its cache slot holds callee
        Call => call(func: u32, callee: u32) -> Stood = tier::call_held;   // a DO_*CALL into the callee the trace follows, no dispatch
        Release => release(word: u64, type_info: u32) = tier::release;   // zval_ptr_dtor
        Copy => copy(word: u64, type_info: u32) -> Zval;       // ZVAL_COPY_DEREF
    }
}
```

Each `kernels!` line expands to `pub(crate) unsafe extern "C" fn <name>(cx: *mut ExitCtx, frame: *mut u8, opline: u32, ...args, out: *mut T) -> Status`, with no `out` for a line with no `-> T`, in a `mod` the invocation names, and one entry in the `Symbols` table, `symbols()`, whose match over `lower::Kernel` holds the list to every kernel `lower` calls: the wrapper reconstitutes `&mut Request` from `cx.req`, hands the kernel the frame's room and the opline's index, calls it inside `catch_unwind(AssertUnwindSafe(..))`, writes its value through `out` (a `Zval` as `ZVAL_COPY_VALUE` writes it, never the slot's `u2`), and maps the result to a `Status`, storing a `Bailout` or a panic payload into `cx.pending` and answering `Exception` where the kernel returned with a throwable pending. A kernel that reads its frame finds it by its room (`tier::at_room`) and stands it at the opline, php's `SAVE_OPLINE()` (`tier::stand`), so what it raises is reported there. `= tier::item` names the engine item the kernel serves through: the wrappers' `mod` imports it, so its removal fails the build, and `api-check` writes it into `tier.lock`'s kernels section (§5.3). `interrupt` is `req.limits().interrupt()`, the flag the engine's timer and signal delivery set (design §5.8), taken by `enter` once so that compiled code needs no layout knowledge of `Request`. The wrappers are `extern "C"`, not `"C-unwind"`, because every panic is caught before it reaches compiled code (`research/llvm-research.r1.md` B.4).

Where `pending` lives. An `ExitCtx` is a local of the `enter` that made it, compiled code holds its address for exactly the duration of that call, and a nested `enter` has its own. The nested case, walked: an inner wrapper stores its kernel's panic in the inner context; the inner `enter` resumes it; the unwind crosses the nested `execute` and the outer kernel; the outer wrapper's `catch_unwind` catches it into the outer context; the outer `enter` resumes it; one panic, the inner payload, reaches the request boundary. A bailout in the inner trace is the inner `enter`'s `Err`, the nested `execute`'s `Err`, the outer kernel's `Bailout`, which every kernel propagates from a nested `execute` as it does from any callee, and the outer wrapper's `BAILOUT`. The only request state the crossing still touches is `JitRequest.touched`, which is monotone.

The raw-pointer invariant, restated per fiber stack. `&mut Request` crosses as a raw pointer under the interpreter's own invariant: on one fiber stack exactly one frame chain executes on this request, and compiled code returns before anything else on that stack touches the request. A kernel called from a trace may suspend the fiber, through a native that calls `Fiber::suspend`; the trace's machine frame then waits on the fiber's stack while another fiber's code, interpreted or compiled, touches the request, exactly as an interpreter handler's frame waits across the same switch. Nothing the trace holds is invalidated by that: its frame is on the fiber's own VM stack pages (design §5.11), its `ExitCtx` is a local on the fiber's own machine stack, and the register-resident scalars it holds belong to slots only its own frame can name. What the switch does invalidate, a memory-derived fact about a shared array or object, is what the clobber rule (§4.2) already reloads after any call-effect kernel, and a suspend is inside such a kernel. So the invariant is per stack, and the design writes it that way.

**The entry** (revision 81). A trace's body reads, as it enters, the room it was handed and the `ExitCtx`'s entry fields: where it is entered, where the frame stands as a kernel would say it (`Stood`), the frame's place on the stack, its calls' headers in the request and whether they are ready, and its own number, at `lower::TRACE_AT`. `enter` lays them as it calls the trace's prologue with the body's address; a jump from another trace lays the same fields in code, from where the exit or the link leaves the frame, stands the frame at the exit's opline as `enter`'s landing would, and makes a tail call to the body, so a trace is entered alike whichever way it is reached. A jump reads, first, the request's row of the trace it enters (`enter::Rows`, at `lower::ROWS_AT`): per trace the crossing entered in the request, its headers and whether they are ready, so a trace is jumped to only once the request has entered it through `enter`, which lays its row. An exit jumps only where the entry can be laid in code: it names its opline, or, a link's, it names none and the frame stands where the linked trace opens; its landing frees nothing; and the code runs where it leaves in a frame of that op array, the frame the jump enters on, which in a recursion, whose frames leave through the exits of the frame their header serves, is not always the frame the exit names. `enter` reads the answer against the trace `TRACE_AT` names, the one entered or one it jumped to, and returns it beside the answer (`enter::Answered`), so the exit landed is the exit of the trace that took it. The request's trace number, php's `EG(jit_trace_num)`, is the entered trace's for the crossing; nothing reads it inside a jump.

`enter` does what no exit block can and nothing else. It does not read the exit's word, does not follow a link, and does not enter a side trace: it returns `Exited` and `dispatch` decides (§4.9). `CHECK_EXCEPTION` remains the `Resume` contract, and `INVALIDATE` still does not exist. `PACKED_GUARD` is a flag on the exit a layout guard takes, as php's is, and no side trace's entry type: a side enters with the types its parent's exit knew, an array's without its layout, and holds the layout at its first read by a long key, as php's holds `MAY_BE_PACKED_GUARD`.

Tested at the seam: a hand-assembled body calling `wrapped::step` through an `ExitCtx`; a panicking test kernel resumed at the request boundary; every wrapper under `force`; `jit.mode=exit-fuzz` (G5), as the next paragraph states it; a kernel that re-enters PHP into a compiled root whose kernel panics, asserting one panic at the request boundary with the inner payload; `set_time_limit(1); for (;;) {}` under `force`, whose fatal must be php's to the byte; a `pcntl_async_signals(true)` handler delivered into a compiled loop; and a fiber that suspends from inside a kernel called by a trace and is resumed from another compiled loop.

As ruled on #3055 (revision 40): Under `jit.mode=exit-fuzz` every guard whose exit is right whatever its value holds fails once per process, the interrupt guard included; the interpreter continues at the landing, and the run must match the oracle byte for byte. A jump's direction guard and `push_call`'s refusal are not failed: their exits are right only where their condition holds (#3055).

### 4.7 `policy`, pure


Nothing here touches a request, a frame, a lock or a table. A `Claim` owns its word's holder instead of borrowing the word: a claim made on a request thread is settled on the compiler's thread (§4.8), after the request that made it may have ended, and the epoch its holder holds keeps the word alive for at least as long as the claim does. Why a claim is a value and not a boolean: the word is engine-shared, and if the thread that won the compare-and-swap leaves without a release store, because a kernel panicked under `step` or a `Bailout` came out of recording, the root stays `recording` for every request that follows, never compiled, never blacklisted, and silent. A `Claim`'s `Drop` is the store a panic would otherwise skip; the stop it records is php's `COMPILER_ERROR` (§A.4), and it counts an attempt, so a root that panics sixteen times is blacklisted.

Directives keep php's names and defaults so an oracle configuration replays unchanged: `opcache.jit` (php's CRTO number or word; `function` and any trigger other than `HOT_TRACE` are accepted, logged once at startup, and run as tracing, because there is one tier and no optimizer, §C.2 item 4; `off`, `disable` and `0` are `Mode::Off`), `opcache.jit_buffer_size` 64M (zero is `Mode::Off`), `opcache.jit_hot_loop` 61, `opcache.jit_hot_func` 127, `opcache.jit_hot_return` 8, `opcache.jit_hot_side_exit` 8, `opcache.jit_blacklist_root_trace` 16, `opcache.jit_blacklist_side_trace` 8, `opcache.jit_max_root_traces` 1024, `opcache.jit_max_side_traces` 128, `opcache.jit_max_exit_counters` 8192, `opcache.jit_max_loop_unrolls` 8, `opcache.jit_max_recursive_calls` 2, `opcache.jit_max_recursive_returns` 2, `opcache.jit_max_polymorphic_calls` 2, `opcache.jit_max_trace_length` 1024, `opcache.jit_debug` (php's bit names). Two engine-only directives: `jit.mode` (`tracing`, `force`, `exit-fuzz`) and `jit.compile` (`thread`, `inline`). `jit.mode` names the mode over `opcache.jit=off`, `tracing` and directives that set none, and not where the directives set say php's tier never starts, `opcache.jit=disable`, a setting php refuses or a zero `opcache.jit_buffer_size`: that program is about having no tier, so the interpreter serves it, and the lane writes no line (#3136's ruling, revision 58). Both are accepted from any host, because a startup ini has no way to know its host and php's own `opcache.jit_debug` is likewise available everywhere; `force` and `exit-fuzz` log one line at startup, and `inline` is a legitimate production choice for a short-lived CLI process. All are system ini: engine state is immutable after `Engine::new` (design §4.4), so `ini_set('opcache.jit', ...)` at run time is not yet honoured: the tier reads startup ini alone, and #3139 builds php's switch, which makes op arrays persisted after it countable.

Tested at the seam with no engine: `from_ini` against php's `zend_jit_parse_config_num` cases (`on` is 1254, `function` is 1205, `disable`); the state machine as a table, one row per `(State, Start, Outcome)`, driven over a `Word::default()` through a `Holder::Root` on a fixture `Published` and asserting `read` after each `settle`, including that sixteen aborts take sixteen threshold crossings and blacklist a root, that a side's exit, whose heat runs on through its attempts, is blacklisted by the abort that finds its heat at `opcache.jit_hot_side_exit` plus `opcache.jit_blacklist_side_trace`, its ninth at php's defaults, and that an exit that grows none is blacklisted at the firing that brings its heat there (revision 56), that `claim` returns `None` when the word is not cold, that a `Claim` moved to another thread and dropped there leaves the word `cold` with one more attempt and zero heat; that `read(&Word::sealed())` is `Blacklisted` and `claim` on it is `None`, the layout invariant; dump lines diffed against the oracle.

### 4.8 `compiler`: the pipeline, on its own thread

```rust
pub(crate) struct Job { recorded: Recorded, claim: Claim, name: TraceName }   // name: the place the `TRACE start` line names (revision 34)
pub(crate) struct Compiler { /* under Thread: the engine's tier::Worker and the queue its body serves, Mutex<VecDeque<Job>> with a Condvar */ }
impl Compiler {
    pub(crate) fn new(shared: &Arc<Shared>) -> Compiler;     // a worker under Compile::Thread and none under Mode::Off; its thread starts with the first job
    pub(crate) fn submitter(&self) -> Submitter;             // laid into each request's JitRequest, so a submission reads no engine state (revision 66)
    /// Runs every queued job to completion on the calling thread, and waits for the worker's. Tests.
    pub(crate) fn drain(&self);
}
#[derive(Clone)] pub(crate) struct Submitter(/* the Compiler's worker and queue by Arc, or none: inline */);
impl Submitter {
    /// `Inline`: runs `pipeline` here, its lines added to `lines`, and answers the `Outcome`. `Thread`: enqueues, wakes the worker and answers none.
    pub(crate) fn submit(&self, shared: &Shared, job: Job, lines: &mut Vec<u8>) -> Option<Outcome>;
}
/// `types::build` over the record and its view, then `shared.backend.compile` under the job's name,
/// then `publish` into the table of the epoch the claim holds, then `policy::settle(claim, &outcome)`.
/// Each failure is mapped by one rule, `Abort(stop)` where php recovers and `Blacklist(stop)` where it
/// does not: an off-list `Stop`; an `Abort` from `build` or `compile`, by the stop it carries; a bound's
/// `Full`, `Blacklist(Stop::TooManyTraces)` or its sibling, and `Full::Code`, `Abort(Stop::CompilerError)`
/// (revision 31); a malformed body and a stage that panics, `Abort(Stop::CompilerError)`. The stop and end
/// lines are added to `lines` (revision 34, until #3040 rules).
pub(crate) fn pipeline(shared: &Shared, job: Job, lines: &mut Vec<u8>) -> Outcome;
```

Design it twice on where the pipeline runs:

| | (A) On the request thread, inside the safepoint | **(B) Chosen: one worker per engine, inline on request** | (C) A pool |
|---|---|---|---|
| What the winning request pays | record, build, lower, publish, in its own latency | record, and a queue push | the same as (B) |
| What other requests see | `recording` at the word, `Continue` | the same, for as long as the queue is deep | the same |
| Determinism for tests | complete | complete under `inline`; `force` and `exit-fuzz` imply it | complete under `inline` |
| Memory limits | the compile's allocations count against the request's `memory_limit` | they do not, as php's buffer does not (unverified) | the same |
| Threads per engine | none | one | N, and a scheduler |
| Where a compile panic surfaces | the request boundary | the pipeline's `catch_unwind`, on the worker or inline, reported as php reports a failed compile, `TRACE n abort (JIT compilation error)` where `jit_debug` asks, the claim settled as `CompilerError` | the same |

(B) is chosen. A trace is entered on the next visit to its root in every column, which is php's behaviour, so a request never waits for a compile in any of them; what (A) makes it wait for is its own. (C) is a scheduler for a queue that G7 says holds one job at a time on the kernels; if a request-shaped corpus fills it, the worker count is a `Policy` number and nothing else changes.

What the worker touches. A `Job` is a `Recorded`, which holds the epoch, and a `Claim`, which owns the holder of its word; the worker reaches `Shared` through its own `Arc`. It touches no request, no frame and no map pointer, which is the same discipline compiled code keeps (§E.7); the epoch the view holds keeps the engine's interned strings its units name, so a job outlives the engine that made it (revision 34). A trace compiled for a unit the cache has since evicted is published into the epoch and freed with it, which is correct and costs one compile. The worker is the engine's `tier::Worker`, as ADR-0010's Threads has every thread the engine runs: started through the engine's one home with the first job, parked between jobs, joined before every fork once the job under way is done and woken after it in the process that asked, so a parked worker refuses no `pcntl_fork` and no php-fpm master's fork (revision 34). `Compiler::drop` drops the jobs still in the queue, whose claims settle themselves, and joins the running one; `JitEngine`'s field order puts `compiler` before `shared`, so the worker is gone before what it shares drops. A panic in `publish` cannot poison the table: `publish` is transactional and the lock is taken with `PoisonError::into_inner`.

The dump. `hot` writes the start line and the pipeline the stop and end lines, each to the request it runs on, which is where php's `jit_debug` output goes. A worker could not keep php's order, so a `jit_debug` that asks for a root's `stop`, `compiled`, `abort` or `blacklisted` line compiles inline, as `force` and `exit-fuzz` do, and the oracle diff of `TRACE` lines runs inline under `[regime.jit-inline]`, which sets no `jit.compile` (revision 34; #3040 rules it). A recording that stopped on a failed attempt is settled by the pipeline on the request at once under either setting, as php writes its abort before an inner loop's repeat; only one that compiles is submitted. Under `Compile::Inline`, `submit` is `pipeline` on the calling thread, which is what every per-commit test runs; under `Thread`, `drain` is what a test calls after a request to make the queue empty before asserting a word's state. A request that submitted a trace to the worker claims no word, as while it records, until the trace's word no longer reads recording and, for a loop's trace closed at its header, until the next loop or return site it visits, where php's interpreter would have entered the trace already (`dispatch::Submitted`; revision 55). What `dispatch::quiet` holds is kept as built, as Mitchell ruled on #3191 (revision 71): it keeps (B)'s "a request never waits for a compile", where waiting for a loop's own job would give php's order exactly, but a busy worker makes that wait unbounded, which php's inline compile never is.

Tested at the seam: `pipeline` over a fixture `Recorded` and a `Claim` on a fixture word, asserting the `Outcome` and the word's state for each failure of each stage, including a panicking fixture, with no backend but `dump`; and, natively, a `Thread` test that submits from four threads, drains, and finds every word `compiled` or `blacklisted` and no trace published twice.

### 4.9 `dispatch`: the one machine

```rust
pub(crate) enum Next { Continue, Enter(TraceId), Resume(FrameRef), Bail(Bailout) }

/// The one state machine over a word, for either home. A sealed word reads `Blacklisted` and
/// takes the last arm.
#[inline(always)]
pub(crate) fn visit(req: &mut Request, frame: FrameRef, word: &Word, holder: impl FnOnce() -> Holder, start: Start) -> Next {
    match policy::read(word) {
        State::Compiled(id) => Next::Enter(id),
        State::Cold => {
            let policy = &tier::state::<JitRequest>(req).shared.policy;              // the request's state, no lookup (revision 66)
            if policy::bump(word) >= policy.threshold(start) {
                if record::recording(req) { return Next::Continue }                    // php bumps and does not trace while JIT_G(tracing) (revision 30)
                match policy::claim(holder(), policy, start) { Some(claim) => hot(req, frame, claim), None => Next::Continue }
            } else { Next::Continue }
        }
        State::Recording | State::Blacklisted => Next::Continue,
    }
}

/// The cold path: record, submit, resume where recording stopped. Recording is exclusive per request.
#[inline(never)]
fn hot(req: &mut Request, frame: FrameRef, claim: Claim) -> Next {
    let _recording = RecordingGuard::set(req);                                       // sets the request's exclusion, php's JIT_G(tracing), and clears it on drop: a panic, a bailout or a destroyed fiber's unwind clears it
    match record::run(req, frame, claim.start()) {
        Ok(recorded) => { tier::state::<JitRequest>(req).submitter.submit(Job { recorded, claim }); Next::Resume(req.stack().current()) }
        Err(bailout) => Next::Bail(bailout),          // the claim drops here and settles itself
    }
}

/// From a `Func` word: what `Jit::safepoint` is. Here, and only here, `Continue` means "nothing happened".
/// Outlined: only a `Bound::On` engine binds `Jit`'s loop and asks it (§4, revision 59).
#[inline(never)]
pub(crate) fn safepoint(req: &mut Request, frame: FrameRef, site: Site, held: Held<'_>) -> Flow {
    let state = tier::state::<JitRequest>(req);                                       // one type check, no lookup (§2.2, revision 66)
    if state.shared.policy.mode() == Mode::Off { return Flow::Continue }              // asked under Off all the same, no word is read or written
    let at = site.idx();
    let holder = || Holder::Root { epoch: req.epoch(), func: held.func(), at };       // a hold on the request's epoch, as `Recorded.view`'s (§4.1)
    match visit(req, frame, held.word(req, at), holder, site.into()) {                // the word at the held op array's offset, no frame lookup
        Next::Enter(id) => run(req, frame, id),
        Next::Continue => Flow::Continue,
        Next::Resume(f) => Flow::Resume(f),
        Next::Bail(b) => Flow::Bail(b),
    }
}

/// Trace to trace, until something is not compiled. A trace has run by the time anything is
/// returned, so `Continue` from an exit's visit is `Resume` here.
#[inline(never)]
pub(crate) fn run(req: &mut Request, mut frame: FrameRef, mut id: TraceId) -> Flow {
    let table = &req.engine::<JitEngine>().shared.table;
    let Some(first) = table.get(id) else { return Flow::Continue };                   // not compiled after all (§3.2, §4.5): nothing ran
    let mut trace = first;
    loop {
        let Exited { exit, frame: f } = match enter::enter(req, frame, &trace) { Ok(x) => x, Err(b) => return Flow::Bail(b) };
        frame = f;
        let ex = &trace.exits[exit.0 as usize];
        if let Some(link) = ex.link {
            match table.get(link) { Some(t) => { id = link; trace = t; continue }, None => return Flow::Resume(frame) }   // the window §3.2 names
        }
        let holder = || Holder::Exit { epoch: req.epoch(), trace: id, exit };
        match visit(req, frame, &ex.word, holder, Start::Side { parent: id, exit }) {
            Next::Enter(side) => match table.get(side) { Some(t) => { id = side; trace = t }, None => return Flow::Resume(frame) },
            Next::Continue => return Flow::Resume(frame),
            Next::Resume(f) => return Flow::Resume(f),
            Next::Bail(b) => return Flow::Bail(b),
        }
    }
}
```

**The exclusion is the request's** (revision 30, #2999). php excludes a second recording with `JIT_G(tracing)`, one flag per thread that `zend_jit_trace_hot_root` tests and sets around the recorder (`Z/ext/opcache/jit/zend_jit_trace.c:8140`, `:8170-8173`) and that no fiber switch saves; `EG(jit_trace_num)`, which `zend_fiber_vm_state` does save, numbers the trace executing and excludes nothing. Here the exclusion is request state outside the switch, set by the recording guard and cleared when the guard drops: on the recording's return, on a panic, or on the unwind that destroys a fiber suspended inside it (design §5.11). A resumer therefore records nothing while a fiber's recording is suspended, and a fiber started inside a recording records no root of its own, as php's do; a fiber suspended inside a recording and kept alive holds the exclusion until it is destroyed or the request ends, which is php's behaviour as well.

`visit` is the machine for both homes; the only thing a home contributes is the `Holder` it would give a claim, and it is a closure so that the compiled and the cold-below-threshold paths, which are every visit but one, take no hold on the epoch. A sealed word never crosses a threshold, so a root holder is never built for a request-scoped op array, whose unit no epoch holds; the invariant is written once, in `policy` (§4.7). The exclusion is read at an activation alone, before its word, one load of the request's state beside the engine's, so it costs nothing at a loop header or a return and nothing under `Off`; php reads `JIT_G(tracing)` only after a crossing (`php-src-jit-hot-root.txt:30-33`), a difference no program observes (revision 30). `hot` never touches the word: the claim holds it. Recording ran the program forward, so `hot` resumes wherever recording stopped, and a `Threw` stop resumes in the frame `HANDLE_EXCEPTION` runs in (§4.1). The compiled trace is entered on the next visit to the root, as in php: a visit that finds a word compiled hands its id to `run` (revision 36). `run` follows links without reading a word, because a link is a build-time fact on the exit, enters side traces by the id in the exit's word, and borrows each trace from the table, whose slots are written once and live as long as the epoch the request holds (§4.5), so entering a trace takes no hold of its own; the one hold `dispatch` takes is a holder's, on the claim path only. The three meanings of "not compiled" are stated on the three places: at a root whose slot is empty nothing ran and `Continue` is right; after an exit a trace did run, so a missing link or side target is `Resume` of the landed frame; and a word that reads `Recording` or `Blacklisted` at an exit is `Resume` for the same reason. Two exits are not side exits and `run` visits neither word: one with a link, which it follows, and a trace's `leaves`, the exit a trace that does not loop ends through, php's `zend_jit_trace_return` to the interpreter; at any other exit that enters nothing, `run` writes php's `TRACE n exit m` line where `opcache.jit_debug` asks for it, as `zend_jit_trace_exit` writes it unless the interrupt is raised or the request records. An exit's word is bumped toward `opcache.jit_hot_side_exit` and, past it, claimed under `Holder::Exit` for a side trace recorded from the exit's landing with what the exit knew of its frame's slots, php's stack map, as its entry types, published into the same id space and entered by the id the word then holds; an exit that names no opline, a table's jump or a call that may be another's, which leaves the frame where it stood, is claimed as any other, and its side trace, recorded from where the frame stands, holds that opline at its first op, php's IP guard (`zend_jit_trace_opline_guard`), compiled code comparing it with where `enter` found the frame, through an exit that names none and grows a side of its own (revision 67); one that grows none, php's `ZEND_JIT_EXIT_TO_VM`, is claimed by nothing and blacklisted at the firing that brings its heat to `opcache.jit_hot_side_exit` plus `opcache.jit_blacklist_side_trace`, writing php's `---- EXIT m/k blacklisted` and no line after (revision 56), and a recording that stops at a compiled trace's root enters it there, as php's interpreter goes on at that opline, whose handler is the trace (revision 52). As built (#3229's ruling, revision 81), a link and an exit whose side trace is published are jumps in the trace's own code (§4.3, §4.6), and `run` meets them only where the jump found no trace or the request's row unready: the first entry of a side in a request, which lays its row, and every exit that grows none. `run` goes on from the trace that answered, which a jump may have entered.

A return root is php's: the caller's opline past the call (`ZEND_JIT_TRACE_START_RETURN` on `opline + 1`), whose counter is armed only where a compiled trace returns into a caller that has no trace of its own (`zend_jit_trace_setup_ret_counter`, `Z/ext/opcache/jit/zend_jit_trace.c:3404-3418`). `Site::Return`, the callee's `RETURN`, bumps and claims nothing (#3036). So a return's site visits no word of the callee's: `dispatch::safepoint` reads the landing past the call its caller stands at, which reads sealed, and is left, until a compiled trace armed it; one compiled is entered and one hot is claimed, under `Holder::Landing`, the `RETURN` stepped first so that the trace enters or records in the caller at the landing, as php's interpreter has returned before the landing's handler runs. What a trace arms is `record::landings`, php's calls of `zend_jit_trace_setup_ret_counter` as its code generator makes them, the opline past each call into the root's op array for a recursive call and, for a trace that hands on to another trace or to the interpreter, past its last opline where that is a call, an `include` or `eval` or a `yield`, and past the call each frame below the one it ends in made; the compiler arms them when the trace is published, where `opcache.jit_hot_return` is not zero. A trace or a recording that leaves its frame at an armed landing visits it, as php's interpreter runs the handler of the opline it goes on at, except a trace's own root, where php's `zend_jit_trace_exit` runs the opline's own handler, and a recording that stops at a call's activation visits that entry's word, a trace just published at a `recursive call` stop, which stands at its own root, entered there as a loop's is (revision 62); and a return past a trace's lowest frame with no opline recorded after it is held to the opline the trace links at or goes back to, php's IP guard in `zend_jit_leave_func` (revision 61), which takes no exit where it fails: the trace escapes, as php's `jit_stub_trace_escape` does, with no exit line and no word, and the interpreter goes on through the handler of the opline the return left the frame at, the landing's trace where one is compiled there (`lower::ESCAPED`, `enter::Left::Escaped`; revision 64).

Tested at the seam: `visit` as a table over `(State, Start)` on a `Word::default()` and a `Word::sealed()` with a fixture engine, asserting `Next`; `visit` with the request's exclusion set at a threshold crossing, asserting `Continue` and a bumped word; a fiber suspended inside a recording and never resumed, asserting no root recorded on the resumer until the fiber is destroyed, and one after (revision 30); a witness whose destructor runs a hot loop inside a recording, asserting one `TRACE start` line, a second root recorded on the next request, and the exclusion clear after a panicking fixture recording; `run` with two hand-assembled traces, one linking to the other and one exiting to a cold word, asserting the sequence of entries through a `Probe`-style counter kernel and that the return is `Resume` of the landed frame; and, under `force`, that every witness enters through `safepoint` and returns through `run` with the oracle's output.

## 5. The kernel face: where the `extern "C"` wrappers live

### 5.1 Design it twice

| | (A) In `php_engine`, by macro beside each kernel (§E.8) | **(B) In `php_jit::enter`, by one `kernels!` list (chosen)** |
|---|---|---|
| Can it exist there | only with reference parameters, since dereferencing `*mut Request` is `unsafe` and `php_engine` forbids it; the soundness obligation then rests on the caller and is documented nowhere in the type | yes; the two raw-pointer dereferences are in the crate that owns the calling convention |
| `php_engine`'s public surface | grows by one `extern "C"` item per kernel, roughly three hundred, for exactly one caller | grows by zero items; the kernels themselves become visible to `php_jit` under `tier.lock` (§5.3) |
| Knowledge of the JIT's convention (`Status`, `opline` as index, out-pointer) | inside `php_engine` | inside `php_jit` |
| Drift between the list and the kernels | none; the wrapper is generated at the definition | a signature change in `ops` fails `php_jit`'s build, because the wrapper calls the kernel; no checker |
| Deletion test | delete the macro and the wrappers reappear in `php_jit` once, by macro: nothing spreads | delete the list and each wrapper reappears at its call site in `lower`, three hundred times: it earns its keep |

(B) is chosen. The wrappers are not `php_engine`'s interface; they are `php_jit`'s interface to its own compiled code, an internal seam, and the price of keeping them there is a hand-written list the compiler checks. The review's proposal to generate the list from `ops.toml` is not taken here and is left for a later revision.

### 5.2 One `step`, not two hundred opcode wrappers

php's `zend_jit_trace_handler` calls the opline's handler (§A.9); here the handler is an arm of the generated `match`, and `step` is that `match` run once. A trace that meets an opline `lower` does not know stores `frame.opline` and calls `php_jit_step`. One item where two hundred would have been generated.

### 5.3 The tier face, and `tier.lock`

`php_jit` sees more of `php_engine` than `api`; it is the only crate that does, `php_macros` depending on no workspace crate (ADR-0007). What it sees is listed and locked, by principle 8: `tier.lock` has two sections. The **face**: `Tier`, `Site`, `Flow`, `Nop`, `execute`, `step`, `Stepped`, `Word` with `halves` and `sealed`, `SafepointIdx`, `FuncRef` with `func` and `word`, `Epoch` with `epoch` and `Epoch::word`, the tier's epoch slot `epoch_state` and `Epoch::tier_state` (revision 27), `ClassId`, `MapPtrRaw`, `Limits::interrupt`, `TraceNum` with `NONE`, `from_raw` and `raw`, `trace_num` and `set_trace_num`, `OplineIdx`, `Request::map_base`, `Request::stack`, the `api` items a tier's state needs (`Extension`, `ExtensionBuilder`, `Refusal`, `Start`, `StartupIni`, `Request::engine`, `Request::state`, `DiagnosticsSink`), the compile worker's `Parked` and `Worker`, which the engine starts and a fork joins (revision 34), and `UnitView` with its builders: a few dozen items, reviewed one by one. The face also holds what the crossing reaches (revision 32): `room` and `at_room`, a frame by its room, php's `execute_data`, and back; `current`, the frame the loop goes on in; `stand`, `SAVE_OPLINE()`; `primed`, the callee an `INIT_*`'s cache slot holds; `free_operands`, an exit's `FREE_OP1` and `FREE_OP2`; and `Diagnostics::raised`. The **kernels**: the engine items the `kernels!` list's lines name after their `=` that the face does not list already, generated into the lock from the list itself by `api-check` and diffed as one section, never kept from the committed file, so a kernel's engine item changing is a lock diff that names it and nothing else; with `step` on the face and `copy` served by `php_heap` alone, that is `tier::release` today (revision 32). `xtask api-check` allows `php_jit` to import from `php_engine` only what either section names.

```rust
/// What a trace may read of the op arrays, literals and engine-immutable classes it touched. Built
/// by the recorder from the request; holds the request's epoch and the ids it accepted; `Send`.
pub struct UnitView { /* private */ }
impl UnitView {
    pub fn new(req: &Request) -> UnitView;                                    // holds req's epoch
    pub fn hold(&mut self, req: &Request, f: FuncRef) -> bool;                // false, and holds nothing, for a request-scoped op array
    pub fn hold_class(&mut self, req: &Request, c: ClassId) -> bool;          // false, and holds nothing, unless the ClassId is published
    pub fn op_array(&self, f: FuncRef) -> Option<&OpArray>;                   // none unless hold accepted it
    pub fn is_main(&self, f: FuncRef) -> Option<bool>;                        // f is its file's own code, php's !function_name (revision 26)
    pub fn parameters(&self, f: FuncRef) -> Option<&[Parameter]>;             // its declaration's parameters, php's arg_info (revision 26)
    pub fn class(&self, c: ClassId) -> Option<&LinkedClass<ClassId>>;         // none unless hold_class accepted it
    pub fn cache_slot(&self, f: FuncRef, slot: CacheSlot) -> Option<MapPtrRaw>; // the engine's offset of f's cache and the slot in it
}
```

`hold` accepts `f` where the view's epoch keeps a row at its offset, which only a held unit's op array has, so a request-scoped one is refused by its offset's kind. `cache_slot` takes the slot, since which field of an opline holds it is the opcode's to say, read where the tier lowers the opline. `UnitView: Send` and `Epoch: Send + Sync` are asserted at compile time beside the types (revision 24).

**The frame's layout** (#3222's ruling, revision 79). The face holds `FRAME`, one `FrameLayout` value that says where a frame's header words stand in its room, php's `execute_data` (`opline`, `info`, `num_args`, `caller`, `returns_to`, `cache`, `annex`, `this`, `closure`), the bits a leave in place refuses by (`leaves_by_kernel`, `caller_loop`) and what a caller and a return slot are numbered from, and where the request's VM stack keeps its top page's top and end, php's `EG(vm_stack_top)` and `EG(vm_stack_end)`, its frame table and a record's fields, and the innermost room's address. Every offset is `offset_of!` over `exec::Header` and `php_heap::VmStack::LAYOUT`, computed in the engine's build, and every accessor is a `tier.lock` item, so a field or a bit added, removed or renamed is a diff of the lock and a moved offset is not; no offset is written in `lower` or in a lock. Beside it the face holds what a call in place needs of the request: `PlainCall` and its `Activation`, the call a recording takes of a push `push_call` laid down plain (`plain_call`, `UnitView::hold_call`, `UnitView::call`), with the flags, entry opline and cache its activation writes where it serves no prologue; `call_image`, the header the request lays out for that call, which `enter` keeps per request and per trace; `stack`, the address of the request's VM stack; `laid`, whether a callee's cache is laid down; and `UnitView::observed`, an observer declared, under which nothing is made in place.

`heap.lock` holds `VmStack::entry`, `push_entry`, `current`, `MapTable::base`, and `FrameRef::func() -> FuncRef` as a frame-header field, and for the frame's layout `VmStack::LAYOUT` with `StackLayout` and `FramesLayout`, and `HeaderImage`, a header's bytes as a push lays them, which code that pushes the same call in place copies.
