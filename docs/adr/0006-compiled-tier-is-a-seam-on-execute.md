# The compiled tier is a seam on `execute` with one engine-level word per safepoint, not a second executor with a per-request feedback table

Revision 1 reserved hooks for a JIT it did not design: a `code` slot on every `Func`, a type-feedback word per cache slot as a per-request map-pointer entry, and "a baseline method JIT that specialises on observed operand types". The JIT research then found that php's own JIT is a trace JIT over its unmodified op arrays, that its per-request feedback is the trace record itself, and that a method JIT built before the interpreter was at parity is what both predecessors measured as negative value. The three JIT design revisions found that every hook revision 1 guessed was either a second representation of a fact the tier already had or a per-opline cost the interpreter would pay for the tier's sake. The decision: `execute` is generic over a trait `Tier` with one hook, `safepoint`, consulted at three places the interpreter already stops, a loop back-edge, a frame's activation after its parameter prologue, and a return, and bound once per `Engine` as a function pointer; beside it `step` runs one handler and reports the edge it took, so a recorder is a loop over the interpreter and not a second copy of it. The tier's mutable state is one opaque two-atomic `Word` per safepoint, allocated by the engine at publication inside the value the unit cache stores, sealed for request-scoped op arrays, whose bits only the tier interprets; the interpreter's own adapter never reads one. Compiled code operates on the interpreter's frames in place, calls the interpreter's kernels through wrappers the tier owns, tests the request's interrupt flag once per loop, and deoptimises by returning an exit number that lands at an opline of the identical frame. The tier lives in one crate, `php_jit`, behind a feature, with two `unsafe` modules, `table::code` and `enter`, so the engine has four `unsafe` homes, not two. The full design is `jit-design.md`.

## Considered options

- **Revision 1's shape: `Func.code` as the entry, a per-request `MapPtr<[Feedback]>`, a baseline method JIT.** Rejected: the word's trace id is the entry, so the slot is a second indexed load; a request cannot see another request's compile, so per-request state cannot hold "is this compiled"; a method JIT over php's op arrays needs an optimizer the design does not build and Mahout's Tier 2 was refused at 2.2× slower.
- **A second executor for compiled code, Mahout's shape.** Rejected by principle 2: a second in-house executor is a second place to be wrong that agrees with the first. The tier runs the same kernels on the same frames and returns to the same loop.
- **A `Mode` trait beside `Tier`, or a `Recording` adapter, or a per-opline flag.** Rejected: two type parameters and four instantiations, one meaningless; a third copy of the loop for one caller; or a test on every opline of every request, the door cost Mahout paid. *Amended 2026-10-09 (#2290, Mitchell): the rejection stands for a mode chosen per request. `Telling` is bound once per engine at start (`tier::Loops::bound`), every instantiation is one an engine binds, and it retires the per-opline test the same bullet rejects (#2032).*
- **`dyn Tier` held by `Engine`.** Rejected: a vtable call per back-edge.
- **A per-opline word, or a word found by binary search.** Rejected: allocated where never used, or a search at every back-edge; the compiler numbers the safepoints and the number rides in a field php leaves unused, so identity against php's dump is unchanged. *Amended 2026-10-21 (#3214, Mitchell): the rejection stands for the safepoint word. A return root's landing word is one per opline of an op array a trace returns into, laid down sealed the first time a tier arms a landing of it, as php's `zend_op_trace_info` is one per opline (`zend_jit_trace.c:8937`, `:3415`); an op array no trace returns into allocates none. A word per call site would need a table from opline to landing, itself per opline, or a search at each return. Any other per-opline word is an amendment of its own.*
- **A frame-header bit for "entry frame of an `execute`".** Rejected: a tier fact written into the heap's frame format; a slot on the per-fiber VM stack is two writes and no bit.
- **Compiling on the request thread inside the safepoint.** Rejected: php's shape because php has one thread; here the engine is `Sync` and the table publishes under one lock from any thread, so the winning request pays a queue push and the compile runs on one worker per engine, with a synchronous mode for every per-commit test.
- **One code mapping flipped RW around each publish.** Rejected: sound on macOS with `MAP_JIT`, unsound on Linux where protection is per mapping; the arena is mapped twice and the execute view is never remapped.
- **Recording across a native re-entry, or without the interrupt flag.** Rejected: a kernel that re-enters PHP during recording can win a claim on another word and start a second recording, and a compiled loop without the flag cannot be stopped by `max_execution_time`; php has a `tracing` flag and a `vm_interrupt` test in every compiled loop for exactly these reasons.

## Consequences

- `php_engine::tier` with `Tier`, `Nop`, `Site`, `Flow`, `execute::<T>`, `step`, `Stepped` and `Word` is month one; `Probe` is the second adapter, so the seam passes the deletion test before `php_jit` exists. G1, the door cost with the tier bound and the buffer at zero, runs per commit from the day the module exists.
- `php_unit`'s `OpArray` gains `safepoints` and `ops.toml` gains the `safepoint` column under ADR-0001; `php_heap`'s `VmStack` gains the entry slot and `current`; `Request` gains the interrupt flag; the compiler asserts that every backward jump has a numbered header.
- `tier.lock` joins the lock set: a face of a few dozen items and a generated section of the kernels the tier may call. `api.lock` is unchanged; the tier is not an extension and is not in the bundle's list, though it declares its state through the extension mechanism.
- `unsafe` is permitted in four places: `php_heap`, `ext/*/src/ffi/`, `php_jit::table::code`, `php_jit::enter`. ADR-0004's two-home sentence is superseded by this one. *Amended 2026-10-05 by design ledger 80 (#1779, Mitchell; the amendment asked on #1883): seven places, as design §4.1 names them: `php_heap`, `php_process`, `ext/*/src/ffi/`, `sapi/*/src/ffi/` (ADR-0008), `timelib_sys`, `php_jit::table::code`, `php_jit::enter`; `xtask unsafe-audit` names the seven.*
- The engine owns three cross-request structures with a lock inside: the unit cache, the trace table and the compiler's queue. None is reachable from an extension; principle 12 stands.
- The backend behind the tier's lowering is a value inside `php_jit`, not a seam of the engine; its decision is a separate ADR on the day the default flips or is refused, with the G1 to G7 readings of the run of record.
- A future reader will want to add `Func.code` back "as a cache of the indexed load". Do not, unless G2 or G3 names that load; the word's trace id is the entry.
- A future reader will want a per-request heat word so that heat resets per request as php's does. The fallback is written in `jit-design.md` §3.3 with F.3 as its criterion, a request-shaped corpus under FastCGI showing no root ever crosses the threshold within one request; it is chosen by that measurement and not by argument.
- A future reader will want `Site::Entry` raised "at the first body opline" as php's counter handler is installed. It is raised by the activation that ran the prologue, which is the same moment without a per-opline compare or a mutable handler table. This file is the answer.
